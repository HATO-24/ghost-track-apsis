# DS-A-07 · 正式会话的长时存档成本标定

> 执行基线 **I6** = `10a48653f9ff5b07517d6eb39c06dbdffb09104e`；本卡**只测量**，交付预算建议与下一优化卡进入条件。
> 原始数据：[measurements.json](benchmarks/a07_save_cost/measurements.json) · [samples.csv](benchmarks/a07_save_cost/samples.csv)

## 1. 结论摘要（观察到的基线，**不是**产品预算）

1. **存档体积随操作日志线性增长**：≈ **2.09 KB / 日志操作**（50→1000 tick：421,869 → 2,160,472 B）。
2. **读档耗时由 replay 主导且超线性**：`load_state` **1.1 s → 50.2 s**（50→1000 tick），
   同期文件读取仅 13→17 ms、`save_state` 仅 76→331 ms。
3. **可见事件数被 1000 条环形缓冲截断**，但**已用 ID 集合继续增长**（220→4,034），
   因此体积增长来自 log + dedup，不来自可见事件。
4. 因此**下一张优化卡的对象是「减少重放工作量」**（checkpoint/增量快照），**不是**压缩。

## 3. 体积与耗时表（3 样本 median；min/max 见 JSON）

| ticks | bytes | tick 总 ms | save_state ms | 文件写入 ms | 文件读取 ms | **load_state ms** | log_ops | bus 可见 | 已用 ID |
|---|---|---|---|---|---|---|---|---|---|
| 50 | 421,869 | 870 | 76 | 2 | 13 | **1,103** | 51 | 220 | 220 |
| 200 | 1,139,120 | 5,231 | 175 | 3 | 13 | **5,166** | 201 | 825 | 825 |
| 800 | 1,925,900 | 29,991 | 293 | 4 | 16 | **35,184** | 804 | 1000 | 3,232 |
| 1000 | 2,160,472 | 40,529 | 331 | 4 | 17 | **50,164** | 1005 | 1000 | 4,034 |

**分项说明**：
- 计时都**不含引擎启动**（同一进程内完成）；`file_read` 只测读文本，`load_state` 单独计时；
- `tick_total` 是该规模全部 tick 的累计耗时（含传感器/物理/事件）；
- 所有 3 次测量的 bytes 完全一致（确定性会话），故 median = min = max。

**增长与主要贡献**：
- bytes ÷ log_ops ≈ 2,093 / 2,112 / 2,394 / 2,149 B → **≈2.1 KB/op**，接近线性；
- `load_state` 相对 tick 数的比值：1.10 s/50 → 25.8 ms/tick；35.2 s/800 → 44 ms/tick；
  50.2 s/1000 → 50 ms/tick → **超线性**，主要来自 replay 中每 op 的重执行（含 sensor/物理/事件重建）。

## 6. 预算建议（**待审查**，不由本卡冻结）

> 明确区分：以下「观察到的基线」是实测；「待审查预算」是**建议值**，需项目负责人/Astra 取舍后
> 才可写入优化卡冻结。**本卡不承诺几秒读档。**

**参考硬件**：AMD Ryzen 7 7435H (16) / Windows 10.0.26200 / Godot 4.7.2 headless / 109 MB 静态内存。

| 项 | 观察到的基线（I6） | 待审查预算（建议起点） | 依据 |
|---|---|---|---|
| 参考负载 | 正式 orbital_sim，1000 tick @1 s | 同左（1000 tick，约 16.7 模拟分钟） | 覆盖一次完整交战机动的量级 |
| 存档 bytes | 2,160,472 B（≈2.1 MB） | **≤ 1.5 MB**（-30%） | checkpoint 化后可去掉大部分 log |
| `save_state` 最大耗时 | 331 ms | **≤ 250 ms** | 体积下降 + 快照代替长 log |
| `load_state` 最大耗时 | **50,164 ms** | **≤ 5,000 ms** | 关键体验项；需 checkpoint，压缩无效 |
| 文件读取 | 17 ms | ≤ 50 ms | 非瓶颈，保持 |
| 正确性 | §4 六项 | **全部保持**（不得用关系统/删事件换性能） | 任务卡硬约束 |

**下一优化卡的进入条件（建议）**：

1. 项目负责人/Astra 确认上表「待审查预算」→ 冻结具体数字进优化卡；
2. 优化卡实现 **checkpoint（周期性完整状态快照 + 少量尾部 log）**，不改事件语义；
3. 优化卡必须**同负载同硬件**复测 1000 tick，并与本卡 I6 数字逐项对比；
4. 优化卡必须证明 §4 六项正确性不退化，且 `load_state ≤ 冻结预算`；
5. 若 1000 tick 仍超预算，再评估增量快照/分片，但不得降低可恢复信息保留要求（A-03/A-04）。
