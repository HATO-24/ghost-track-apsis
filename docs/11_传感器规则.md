## 0　概述

本模型把「探测—定位—识别—确认」拆成可验证的传感器规则。每一次确认都伴随延迟、残差与暴露风险；模型输出 observation、track 与 exposure 三类结构，供上层 UI 与剧情状态使用。

`sensor_model.gd` 是**纯函数层**：输入 = 传感器字典 + 目标字典 + 环境 ctx；输出 = observation / track / exposure。
不依赖 Node、不读写 UI、不 import `state.gd`；`state` / `plot` / `hud` 下一轮通过静态函数接入。

## 1　规则总览

### 1.1　交战六步与传感器（05 §2）

```
探测 ──→ 定位 ──→ 识别 ──→ 解算 ──→ 发射 ──→ 评估
 L1       L2       L3        —        —        L4
```

传感器负责探测（L1）、定位（L2）、识别（L3）与确认（L4）；解算、发射与评估由武器与战斗系统负责。

### 1.2　接触等级（05 附录 B / 07 §1 / 10 §6.3）

| 等级 | 含义 | 达到它的手段 | 本模型中的支撑级 |
| --- | --- | --- | --- |
| L0 | 无接触 | — | `LEVEL_NONE` |
| L1 | 有回波、**仅方位**（无距离解；IR 另给远/中/近三档） | 被动红外 | `LEVEL_IR`（IR 观测） |
| L2 | 定位，舰种未知 | 雷达 / 双平台方位三角测量 | `LEVEL_TRACK`（雷达、LR-4、三角测量） |
| L3 | 分类完成（舰级 / 船厂 / 使用方） | 光学凝视 + 数据库 | `LEVEL_CLASSIFY`（光学凝视完成、ELINT 指纹） |
| L4 | 识别到具体舰名 | IFF 应答 / 信号指纹 / 数据库比对 | `LEVEL_IDENTITY`（IFF 应答） |

> L1 措辞说明：05 附录 B 写「有回波，方位不定」，但 05 §S-01 明确 IR **显示一条持续的方位线**，
> 07 §3 Phase 1的教学又是「两条同方位回波」。本模型按**「仅方位、无距离解」**实现 L1；
> 「方位不定」留给设定侧统一措辞（见 §11 待定 R-1）。

### 1.3　三种传感器 + 识别 / 通信设备（04 §12 口径）

| type | 是什么 | 给什么 | 等级上限 | 暴露 |
| --- | --- | --- | --- | --- |
| `ir` | 被动红外 | 方位线 + 远/中/近三档 | L1 | 无 |
| `radar` | 主动雷达 | 距离 + 方位（+ 稳定跟踪标记） | L2 | **开机即暴露** |
| `optical` | 光学望远镜 | 方位；凝视完成后分类 | L1 → L3 | 无 |
| `optical` / `subtype=lidar` | 激光测距 LR-4 | 火控级精确距离 | L2（不升 L3/L4） | 微弱（仅目标 LWR） |
| `iff` | 敌我识别 | 身份；应答正确 → 友军 | L0 / L4 | 询问即暴露 |
| `elint` | 通信截听 | 方位 + 特征码（**不出接触**） | L3/L4 证据 | 无 |
| `radio` / `lasercom` | 通信 | 链路状态 + 延迟 | 不产生等级 | 发射时暴露 |

> 04 §12：传感器只允许 `ir` / `radar` / `optical` 三种；**激光测距是 optical 子型，不是第四种传感器**。
> IFF / ELINT / 通信属于识别与链路设备，在 schema 里单列 type，但不计入「传感器三型」。

## 2　按舰载传感器架 schema

### 2.1　结构

`SensorModel.all_racks()` 返回：

```jsonc
{
  "ship_id": [                    // 舰 id（字符串）
    {
      // —— 任务要求的必填字段 ——
      "source":    "OCUVF-ID13",          // 传感器来源 / 归属（架归属于谁）
      "maker":     "车肆重工",          // 厂商（06 §3）
      "model":     "CH-IR2",            // 型号（06 §4.3 / 05 §3）
      "type":      "ir",                // ir / radar / optical / iff / elint / radio / lasercom
      "range_km":  60000.0,             // 探测 / 通信距离（06 §4.3 或 05 §3）
      "refresh_s": 1.0,                 // 刷新 / 凝视 / 询问周期
      "expose":    false,               // 开机是否暴露自己
      // —— 扩展字段（规则需要，见 §2.3）——
      "on": true,
      "mode": "被动红外",
      "ref": "06 §4.3"
    }
  ]
}
```

> `source` 与 `maker` 是两个维度：**架属于哪条舰 / 哪个体系**（source），**谁造的这个模块**（maker）。
> `09 §5.6` 的提案 JSON 用 `maker` + `mode`；本模型把 `source` 补成必填，UI「传感器来源」直接用 `source`。

### 3.1　红外阵列（05 §S-01；06 §4.3）

| 型号 | 厂商 | range_km | refresh_s | σ方位 | 虚警率 | 来源 |
| --- | --- | --- | --- | --- | --- | --- |
| MS-IR9 | 明视光学 | **120,000** | 1.0 | 0.4° | 0.02 | 【05】S-01 120,000 km / 300 K / 1,000 m²；【06】§4.3；σ/虚警【定义】 |
| NO-IR7 | 中村光学 | **110,000** | 1.0 | 0.5° | 0.04 | 【06】§4.3（抗震动、比明视近）；σ/虚警【定义】 |
| YW-IR5 | 远望电子 | **90,000** | 1.0 | 0.8° | 0.08 | 【06】§4.3（抗干扰）；σ/虚警【定义】 |
| CH-IR2 | 车肆重工 | **60,000** | 1.0 | 1.2° | 0.22 | 【06】§4.3（虚警多）；虚警率取【09】§5.6 提案 0.22；σ【定义】 |

**IR 判定（05 §S-01）**：

```
热对比 contrast = (T/300K)^4 × (A/1000m²) × shadow(0.6)      ← 300 K / 1,000 m² = 1.0
有效距离 R_eff = range_km × sqrt(contrast)                   ← SNR ∝ 1/R²
Pd = logistic(-10·2·log10(R/R_eff))                          ← 01 §5.3
距离档：R ≤ R_eff/3 → NEAR；≤ 2·R_eff/3 → MID；≤ R_eff → FAR
```
输出：`level_support = 1`，`range_km = -1`（**不给距离**），`range_band` / `band_ref_km` 给 plot 画档位；`bearing_sigma_deg`。
虚警：默认关闭；`ctx.enable_false_alarms = true` 时用 `false_alarm` 掷骰生成 phantom 观测（06 CH-IR2「常把残骸当敌舰」）。

### 3.2　雷达（05 §S-02；06 §4.3）

| 型号 | 厂商 | range_km（探测） | track_range_km（稳定跟踪） | refresh_s | σ距离 | σ方位 | 抗干扰 | LPI | 来源 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| YW-R9 | 远望电子 | **30,000** | **15,000** | 6.0 | 0.25% | 0.15° | 0.2 | 否 | 【05】S-02；【06】§4.3（精度高、耗电、开机即暴露） |
| KD-R6 | 红隼动力 | **28,000** | 14,000 | 6.0 | 0.4% | 0.25° | 0.2 | **是** | 【06】§4.3（低截获概率、精度略低）；track=range/2【定义】 |
| MS-R4 | 明视光学 | **26,000** | 13,000 | 6.0 | 0.3% | 0.2° | 0.5 | 否 | 【06】§4.3（抗干扰强） |
| SC-R2 | 南十字动力 | **20,000** | 10,000 | 6.0 | 0.6% | 0.4° | 0 | 否 | 【06】§4.3（便宜、易被干扰） |

**雷达判定（05 §S-02）**：

```
RCS 因子 = (σ/10 m²)^0.25                                     ← 05 §S-02 以 10 m² 为基准
干扰因子 = 1 − jamming × (1 − 0.30) × (1 − jamming_resist)    ← 05 §E-01「探测距离可到 30%」
R_eff = range_km × RCS 因子 × 干扰因子
Pd = logistic(-40·log10(R/R_eff))                             ← SNR ∝ 1/R⁴（01 §5.3）
稳定跟踪 = R ≤ track_range_eff 且 Pd ≥ 0.5；否则 σ距离 ×3
```
输出：`level_support = 2`（给距离 + 方位）、`range_km`、`range_sigma_km`、`stable_track`、`track_range_eff_km`、`quality`、`expose_self`。
**开机即暴露**：`expose_self = emission_for(sensor)`，见 §6。

### 3.3　光学（05 §S-03；06 未列光学整机 → 型号本文登记）

| 型号 | 厂商 | range_km | refresh_s | 凝视基准 | σ方位 | 来源 |
| --- | --- | --- | --- | --- | --- | --- |
| MS-OT2 | 明视光学 | **15,000** | 8.0 | **40 s @ 8,000 km** | 0.05° | 【05】S-03（15,000 km 可分辨舰级轮廓）；【05】§2.1（识别 40 s @ 8,000 km）；06 未列整机→型号【定义】 |
| NO-OT1 | 中村光学 | **13,000** | 8.0 | 52 s @ 8,000 km | 0.06° | 【05】S-03（口径 0.5–2 m）；【06】§3.1（中村：抗震动、稍近）；【定义】 |

**光学判定（05 §S-03）**：

```
若 sun_illum < 0.05 → 不可见（“阴影区目标就是一粒看不见的沙子”）
R_eff = range_km × sqrt(sun_illum)
Pd = logistic(-20·log10(R/R_eff))
凝视 stare += refresh_s；自舰机动 > 0.02 g → stare 归零重来
所需凝视 = clamp(40 s × (R/8,000 km)², 4 s, 240 s)          ← 05 §2.1 基准；R² 缩放【定义】
stare ≥ 所需 → level_support = 3（分类完成）；否则 1（只有方位）
```
输出：`classification`（舰级 / 船厂 / 角色 / 阵营，来自目标数据）、`stare_s` / `stare_required_s` / `stare_progress`。
**不判身份**：L3 只到「舰级」，不自动给舰名（04 §9.1 的识别阶梯）。

## 4　判定流程

### 4.1　总流程（每个融合周期 1 s，05 §S-07）

```
for 每艘本舰 ship_id:
    架 = SensorModel.sensor_rack(ship_id)
    对每个 track:
        target = {range_km, bearing_deg, rcs_m2, temp_k, area_m2,
                  transponder, iff_code, emissions[], classification{}}   ← 来自 sim / state
        obs[]  = SensorModel.detect_all(ship_id, target, ctx)             ← 每个开机模块一次
        track  = SensorModel.update_track(track, obs, t, {"track_id": id})← 融合等级/位置/身份
    对每个 track:
        track = SensorModel.age_track(track, t)                          ← 衰减 / 陈旧 / 协方差
    exposure = SensorModel.emission_state(ship_id, {"on": on_map,
                "seconds_on": sec_map, "transmitting": tx_list})          ← 自舰暴露
```

### 4.2　单传感器

| 传感器 | 判定要点 | 输出等级 | 等级依据 |
| --- | --- | --- | --- |
| IR | `los` + 热对比 + R² logistic | L1 | 05 §S-01 / 01 §5.3 |
| 雷达 | `los` + RCS^¼ + R⁴ logistic + 干扰 | L2 | 05 §S-02 / 01 §5.3 |
| 光学 | `sun_illum` + R² logistic + 凝视计时 | L1 → L3 | 05 §S-03 / §2.1 |
| LR-4 | 已有方位 + 4,000 km + 精确距离 | L2（不升） | 05 §S-04 |
| IFF | 2,000 km + 应答码 | L4（友军）/ 不明 | 05 §S-06 |
| ELINT | 对方在发射 + 截获距离 + 特征码 | 信号（L3/L4 证据） | 05 §S-05 |
| 通信 | 视线 / 干扰 | 无等级，只给链路 | 05 §C-01 / E-03 |

### 4.3　等级融合（证据制）

每个 track 维护 `level_evidence = {1: t1, 2: t2, 3: t3, 4: t4}`。
**获得支撑级 S 的观测时，同时刷新 1..S 的全部下级证据**（拿到 L4 = 同时具备分类与定位信息）。

当前等级：

```
level = 1（有航迹即 L1，05 §S-07「失去跟踪不删除」）
对 L ∈ {2,3,4}：
    if now − level_evidence[L] ≤ LEVEL_VALID_S[L]: level = max(level, L)
```

| 证据级 | 有效期（自最近一次写入） | 等效衰减 |
| --- | --- | --- |
| L4 | 30 s | L4 → L3 @ +30 s |
| L3 | 90 s | L3 → L2 @ +90 s |
| L2 | 210 s | L2 → L1 @ +210 s |
| L1 | ∞（记忆地板） | 不降，只标陈旧 |

> 05 §S-07 只规定「逐级降级 L4→L3→L2→L1」，**没给时间**；30/90/210 s 为【定义】，按 07 的 12–15 分钟节奏校准，
> 可用 `age_track(track, now, {"stale_after_s": …, "memory_keep_s": …})` 或直接改 `LEVEL_VALID_S` 调。
> 关键性质：**只有 IR 在刷新不会保住 L4/L3**——身份证据不刷新就会逐级掉下去；这也让「开机时长」和「记忆」变成资源。

### 4.4　陈旧与协方差

| 量 | 规则 | 来源 |
| --- | --- | --- |
| `stale` | `now − last_update_t > 30 s` | 【定义】；state.gd `stale = age > 30` |
| `age_s` | 距最近一次有效刷新 | 05 §S-07「最后更新时刻」 |
| `covariance` | 见 §7；随时间增长 | 05 §S-07「协方差椭圆随时间变大」 |
| `retire_hint` | `age > 300 s` 只作提示，**不删除** | 05 §S-07「失去跟踪不删除」 |

## 6　暴露 / EMCON 规则

### 6.1　核心规则：**开机就是暴露，开推进就是点亮自己**（01 §5.1）

| 发射器 | 权重 | 截获方式 | ELINT 截获距离 | 被定位时长 | 依据 |
| --- | --- | --- | --- | --- | --- |
| 主动雷达 | **1.0** | ELINT 全向 | range × 1.5（YW-R9 → **45,000 km**） | 20 s | 【05】S-02 + 附录 A；系数/时长【定义】 |
| IFF 询问 | 0.6 | ELINT 全向 | 2,000 × 2 = **4,000 km** | 12 s | 【05】附录 A「询问即暴露」；系数【定义】 |
| 无线电发射 | 0.5 | ELINT 可测向 | 120,000 × 0.5 = **60,000 km** | 40 s | 【05】C-02「每一次通话都在告诉对方你在哪」 |
| 激光测距 | 0.25 | **仅目标 LWR** | **0**（ELINT 截不到） | 30 s | 【05】S-04「对方有激光告警机就能收到」 |
| 激光通信 | 0.15 | 侧向散射，极低概率 | 384,400 × 0.02 ≈ **7,700 km** | 60 s | 【05】C-01「极低截获概率，但不是零」 |
| IR / 光学 / ELINT | 0 | — | — | — | 【05】S-01 / S-03 / S-05 |

**LPI（06 KD-R6「低截获概率，很难被定位」）**：截获距离 ×0.5、被定位时长 ×2
（KD-R6 → 21,000 km / 40 s；对比 YW-R9 45,000 km / 20 s —— 自测已断言）。

**开机时长 → 定位精度**（05 §S-02「开得越久，被定位得越准」）：

```
progress   = clamp(seconds_on / fix_after_s, 0, 1)
截面 σ     = lerp(1.0°, 0.2°, progress)     ← 先只有方位线，再收敛到可定位
fixed      = progress ≥ 1
```

## 7　误差与协方差

### 7.1　单观测误差（observation 自带字段）

| 传感器 | 方位 σ | 距离 σ | 说明 |
| --- | --- | --- | --- |
| MS-IR9 / NO-IR7 / YW-IR5 / CH-IR2 | 0.4 / 0.5 / 0.8 / 1.2° | **无距离**（三档） | 05 §S-01 只给方位；σ 为【定义】 |
| YW-R9 / KD-R6 / MS-R4 / SC-R2 | 0.15 / 0.25 / 0.2 / 0.4° | 0.25% / 0.4% / 0.3% / 0.6% × R（有下限） | 05 §S-02 给距离；σ 为【定义】 |
| MS-OT2 / NO-OT1 | 0.05 / 0.06° | 无距离 | 05 §S-03 纯方位 |
| LR-4 | 0.05° | **0.2 km** | 05 §S-04 精确距离；σ【定义】 |
| IFF | 1.0°（询问方向） | — | 不给位置 |
| ELINT | 1.0°（测向有限） | — | 05 §S-05 只给方位 |

### 7.2　航迹协方差（`covariance_at(track, now)`）

```
横向 σ_cross  = R × σ_方位(rad) + 0.5·a·age_b²        ← 方位角误差在距离上的弧长 + 未知机动增长
径向 σ_radial = σ_距离 + 0.5·a·age_r²                  ← 测距误差 + 未知机动增长
位置 σ_pos    = sqrt(σ_cross² + σ_radial²)
协方差椭圆    = semi_major = max(σ_cross, σ_radial)，semi_minor = min(...)
仅方位（L1）  = 径向用三档档位宽（R_eff/6）+ 增长；即“没有距离”的巨大椭圆
a = 0.00098 km/s²（0.1 g，04 §8 机动基线）             ← 增长系数【定义】
```

`age_b` / `age_r` 分别用 `last_bearing_t` / `last_range_t`：**雷达距离和 IR 方位可以各自老化**，
所以「IR 一直在刷新、雷达关机」时等级会掉、距离椭圆会继续变大——这就是 05 §S-07「不确定性可以被画出来」。

### 7.3　探测概率（01 §5.3）

```
SNR_dB = −10 · n · log10(R / R_ref)，R_ref 为 Pd = 0.5 的距离
         n = 2（IR / 光学 / ELINT 单程）或 4（雷达 / 激光测距双程）
Pd = 1 / (1 + exp(−0.5 · SNR_dB))
```
性质：距离翻倍 → 雷达 Pd 从 0.5 掉到 ~0.05（R⁴）；IR 掉到 ~0.12（R²）。
`SensorModel.detection_pd(30000, 30000, 4) == 0.5`、`detection_pd(60000, 30000, 4) < 0.2` 已被自测断言。

## 10　下一轮接 state / plot / hud 的接口建议

> 本轮不改这三个文件；下面是**最小迁移路径**。原则：`sensor_model.gd` 保持纯函数，UI 只读。

### 10.1　`state.gd`（建议由下一轮 P1c 执行）

1. **按舰架替换全局 `sensors`**：
   ```gdscript
   const SensorModel := preload("res://scripts/sensor_model.gd")
   var racks: Dictionary = SensorModel.all_racks()      # 或从 data/scenario.json 载入
   var sensor_on: Dictionary = {}                        # { ship_id: {model: bool} }
   var emcon: Dictionary = SensorModel.emcon_plan("harmattan")
   ```
   当前 `state.gd` 的全局 `sensors` 列表仍是旧全局配置：
   - `S-07` 是**融合系统**不是传感器 → 用常量 `FUSION_PERIOD_S` 或 `state.fusion_period`；
   - 旧型号名统一改为本文 §3 的 `MS-IR9` / `YW-R9`；
   - 「光学」是模式不是型号 → `MS-OT2`。

2. **tracks 增字段**（保留现有 `r/v/range/bearing/level/age/stale`，由 `refresh()` 继续算几何）：
   ```gdscript
   "last_update_t": float, "last_bearing_t": float, "last_range_t": float,
   "level_evidence": Dictionary, "covariance": Dictionary, "sources": Array,
   "classification": Dictionary, "identity": Dictionary, "iff_status": String,
   "signal": Dictionary, "age_s": float, "retire_hint": bool,
   ```
   适配层（每 1 s）：把 `r/v` 派生的 `range/bearing` + 舰元数据 + `emissions` 拼成 target，
   调 `detect_all` → `update_track`；每帧调 `age_track` 更新 `level/age/stale/covariance`。

3. **暴露状态**：`state.emission = SensorModel.emission_state(selected_ship_or_own,
   {"on": on_map, "seconds_on": sec_map, "transmitting": tx_list})`；雷达 ON 时写日志 `EMIT`。

4. **数据源迁移**：最终 `data/scenario.json` 提供 `ships[]` + `ships[].sensors[]`，
   `sensor_model.gd` 的 `SHIPS` / `RACK_BLUEPRINTS` 退化为 fallback（下一轮可加 `load_racks(json)`，本轮不做）。

### 10.2　`plot.gd`

| 等级 | 画什么 | 数据 |
| --- | --- | --- |
| L1 | 从本舰出发的**方位线**（不画点），线宽随 `quality`/`range_band`；标注「仅方位 / 陈旧」 | `bearing_deg`、`bearing_sigma_deg`、`range_band`、`stale` |
| L2 | 位置点 + **协方差椭圆**（semi_major/minor、方位）；可画 `stable_track` 与否 | `covariance`（`semi_major_km` / `semi_minor_km`） |
| L3 | 舰级 / 船厂 / 阵营标签 | `classification` |
| L4 | 舰名 / 舷号 / IFF 友军标记 | `identity`、`iff_status` |
| 暴露 | 本舰 `EMIT` 标记 + ELINT 截获半径环 / 雷达波束脉冲 | `emission_state.emitters[].elint_range_km` |
| 光学 | 凝视进度环（`stare_progress`）；阴影区目标不画光学框 | `stare_progress`、`sun_illum` |

现有 `state.gd` 的 `_derive()` 已经给 `bearing/range/closing/alt`，plot 不需要自己算几何；
`bearing_only` / `stale` 两个现有字段可直接由模型输出驱动（302° 陈旧接触即 L1 bearing-only）。

### 10.3　`hud.gd`（按 09 §5.3 的右区「传感器架」页）

1. 行数据 = `SensorModel.sensor_rack(选中舰)`：型号 / 厂商 / 模式 / 距离 / 延迟 / 虚警 / **暴露标记**（`expose`）。
2. ON/OFF → 写 `state.sensor_on[ship][model]`（sim 决定代价：雷达 → `emission_state` 立刻暴露）。
3. 详情区：`expose` 时显示「开机即暴露：ELINT 截获 X km / Y s 后可定位」（来自 `emission_state.warnings`）；
   被动模块显示「24 小时开机不付代价」（05 §S-01）。
4. 接触列表：等级徽标继续用 L1–L4（已有）；`stale` 变灰 + 协方差尺寸；IFF「不明 ≠ 敌意」文案来自 `iff_status`。
5. 规则卡：`开机 = 暴露`、`不明 ≠ 敌意`、`交叉确认`（09 §5.3 已设计，文本可直接对应本模型返回值）。
6. （可选）`main.gd` 启动时打印一次 `SensorModel.run_self_test()` 或 `SensorModel.validate_racks()`，
   与 `Orbit.selftest()` 并列，作为 P1 回归入口。

### 10.4　调用节奏（与 05 §S-07 对齐）

```
渲染帧：只读 state（不跑规则）
融合 tick（1 s，固定步长）：
    for track: update_track(track, detect_all(...), sim_t)
    for track: age_track(track, sim_t)
    emission_state(own, ...)
```
时间加速时按仿真时间推进（02 §9.1），探测掷骰用种子化 RNG（02 §9.2），保证录制重放一致。
