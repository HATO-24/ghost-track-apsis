# UI-03：固定四区、详情层级与执行反馈

状态：五态规格审校可并行；运行时WAIT UI-02/A1及所触业务view冻结。依据[五态规格](../../ui/20261027/five_state_specs.md)、[60](../../60_Astra_UI与文案设计规范_交Sol.md)。

## 1. 目标与现状

常驻画面能回答目标、注意对象、当前选择、下一动作和命令是否生效。旧识别/编制模态将证据、规则、日志、实现说明同时铺开；主屏多个计时/标签争夺视线。用固定空间和按需展开降低负担，不以减少业务数据解决布局问题。

## 2. 基线、依赖与范围

取证main3045311，仅作为旧图/源码来源；执行填写UI-02与A1实际40位SHA，涉及身份/EW新增字段先等相应A02–A04接口冻结。允许HUD布局、输入/焦点/选择状态、只读ViewModel格式与命令/通信摘要，首批巡航/选中/告警；友军AI与部署业务留UI-04/Phase B。不改GameSession状态机、owner融合、物理或存档语义，不全屏复制旧坐标/旧state层。

## 3. 分区、读者与信息层级

顶栏模式/时间/主要目标和关键告警；左栏找可见对象；中央看获准态势；右栏当前对象判断与动作；底栏追踪命令/通信。立即知道、当前动作、核查学习、开发诊断四层分开。地图标签优先选中/交战/任务/紧急项；计数只取可见集合。信息折叠不删观测、不回读隐藏实体。reason/来源/年龄需翻成人话，但保留未送达、拒绝、执行中、完成不同阶段。

## 4. 实施拆分

1. 把五态规格映射到当前控件/获准view和用户动作，列只读字段、已有事件与缺接口；缺接口另列，不造假战报。
2. 固定四区和主动作位置，目标/识别详情转为右栏/页签，规则/证据/历史展开后可达，避免多层全屏模态。
3. 左栏折叠/筛选、地图渐进标签；保留选择、缩放/态势位置。空列表、目标失效和长名有合理无数据态。
4. 命令/告警按对象与严重度聚合重复项，但不合并阶段；普通更新不抢选择/焦点，不反复弹成功。失败原因近动作，相关详情可达。

## 5. 验收

巡航、选中未知目标、来袭告警、无数据/过期、授权受阻、密集目标/多告警、选择对象消失/读档后恢复分别实测。键盘/鼠标连续操作：后台刷新不改变选择/焦点；模态返回保持态势视角；重要失败不能仅悬停；关闭诊断仍知模式/时效/动作状态。未共享盟军或隐藏敌方不能因标签/统计/告警数量泄露。相同输入的业务事件/资源不因折叠/排序改变。

## 6. 命令与证据

UI-01既有专项＋原C回归，交互改动用少量有意义的正式入口scenario验证选择/焦点/消息阶段，不测试实现细节自比较。1920×1080、1600×900、已核对缩放按UI-02标准留样张；按五态列操作步骤、实际事件/可见来源、前后图、失败补救路径及人工阅读反馈。真实渲染/人工验收未做必须写NOT RUN，不能仅统计字符减少。

## 7. 旧失败/风险

保留既有baseline；发现HUD隐藏ID泄漏归真实消费者修复，不能删负例。折叠/告警聚合不可掩盖请求失败/失联；诊断开关不是获得敌方情报的权限。老化/融合异常仍由业务卡修，布局不把过期数据显示成正常。

## 8. 交付与设计复核

控件/字段/事件映射、有限布局/交互diff、五态前后图、可用性操作记录、回归及未接入点。Astra审层级/留白，Sol审语义，负责人实机体验。尚未实现的协同/编制出击状态只保留设计规格，不宣称联合战役可玩。
