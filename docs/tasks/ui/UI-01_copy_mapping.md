# UI-01：有限页面文案映射与开发说明迁出

状态：文案审校可并行；运行时WAIT A1合入＋本卡范围设计核对。总则见[61](../../61_UI文案台账与实施队列.md)、[60原规范](../../60_Astra_UI与文案设计规范_交Sol.md)。

## 1. 玩家目标与现状

战术主屏能让玩家看懂当前模式、规则和受阻原因；正常模式不再常驻SESSION LIVE/CIC VIEW/不写WORLD/API名等开发说明。当前主屏有硬编码计时/链路，ROE页混入set_roe说明；NOT READY也承载多种不同条件，不能全局替换。

## 2. 基线、依赖和范围

取证main `3045311657609dfe10a133802b93dde2fc8abb79`。开工必须填写A1合入后的实际40位执行SHA；当前PR66未通过，不在其活动分支套UI改动。先核对[台账](../../ui/20261027/copy_inventory.md)，只做**主屏常驻模式/标题与ROE页**的有限映射，列实际行号/候选键清单。通信、识别、损管、编制其余行本卡只审校不顺手全改。允许HUD显示路径和一个轻量文案映射层；不改GameSession状态机、ROE授权逻辑、存档schema、布局总架构或全项目文本系统。

## 3. 读写、语义与可见性

业务服务写状态，A1 owner facade写可见数据，文案映射只读reason/state/参数并输出文字。原始code保留在开发日志/受控详情；正常界面不显示函数/内部ID。模式来自真实入口，未实现/预览明确标记；未知不默认0。ROE、身份识别、TRACK/SOLUTION/FIRE各自含义不变；未知code给“操作未完成/原因待查”的如实入口，不能编造补救建议。UI键是编辑定位，不是已有代码接口。

## 4. 实施和提交拆分

1. 留正式入口前图、触发条件、原文/候选映射；标出确定删除与需要业务新字段的行。新字段另列依赖，缺字段不造数据。
2. 先有限集中映射，参数化安全显示名/单位/年龄；正常/诊断模式有明确边界，保留原始追踪信息。
3. 迁出开发旁白、删除未绑定真实数据的装饰计时/固定LINK OK；受影响字段如实显示未知/不可用或不出现。诊断可用性不能成为读取隐藏实体的后门。
4. 显示实现与实机证据分提交，不修改业务行为以配合候选词；更新台账已实现/待定状态和语义疑点。

## 5. 正负例和兼容

有/无选中、有效/缺失/过期数据、未获FIRE授权、ROE锁定/可编辑、显式预览、未知错误均实测。正常模式无开发标语；关闭诊断后仍能判模式/数据有效性和为何受阻。合法动作结果/业务事件/资源前后不因文案改变；旧seed/profile/存档保留语义。不得用隐藏目标真名作占位，不把身份友军译为可直接指挥，不把已发送译为已执行。

## 7. 历史失败与风险

既有7项full失败不刷新，新增失败单列；A1尚未关闭的真实匿名化/时间/融合问题不得转成UI删字任务。文案清理可能隐藏失败反馈，故必要模式/失效/授权信息必须在当前动作附近可见。
