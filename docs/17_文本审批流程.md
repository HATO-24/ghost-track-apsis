# 文本审批流程 v0.1

> 状态：生效。用户确认：**所有会出现在游戏内的文本，先给用户过目、润色、复核，再进游戏。**
> 叙事文本（无线电、简报、报告、结局）尤其如此。

---

## 1　规则

1. **不自动改游戏文本。** `data/scenario_l1.json`、`hud.gd`、`plot.gd`、`state.gd`、`main.gd` 里任何玩家能看到的字符串，先进入本文的批次表。
2. **一批一表。** 每批包含：ID、文件/位置、当前文本、拟改文本、理由、状态。
3. **状态**：`待审` → `已批准` / `待润色` / `已驳回` → `已应用`。
4. **只有用户说“批准/可以/改”后**，才写入游戏文件。
5. 叙事文本默认不做“教学括号”；教学提示放非叙事的 HUD 提示、监督官笔记，或不做。
6. **游戏内不显示 Act/Phase/关卡/阶段/教程提示**。Act/Phase 只是作者侧结构；游戏里只给一个目标和局面，玩家自由选择。
7. 每批应用后，Lead 跑 headless + 截图，再交用户复核。
