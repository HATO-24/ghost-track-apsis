# 目标与节奏 v0.2（D2）

> 状态：已确认。游戏内不显示 Act / Phase / 关卡 / 阶段提示；玩家只有一个大目标，如何达成、中间发生什么由玩家决定。
> 参考 Highfleet 的节奏：目标明确，路径开放，信息靠现场拼。

---

## 0　原则

游戏内不显示“第几关”“第几阶段”，只显示一个必须完成的目标和一个正在恶化的局面。

---

## 1　节奏

- **一个目标**：例如“阻止清算者完成对 Chronos 的接管”。不是“完成 Phase 1”。
- **路径开放**：玩家可以卡位、谈判、拖时间、撤离、取证、开火；游戏不按清单发任务。
- **事件由世界推动**：时间、第七号令、对方行动、港群反应推动局面；不是“清完这波进下一阶段”。
- **信息靠现场拼**：目标、通信、文书、接触、传言；不用关卡提示解释。
- **失败是结果**：内部报告、声望、审计、后续剧情；没有“任务失败，重试”。

---

## 2　游戏内显示

| 显示 | 不显示 |
| --- | --- |
| 目标 / 命令（例如“阻止接管 Chronos”） | Act 编号、Phase 1/3、关卡名 |
| 执行窗口、时标、ROE | “教学阶段”“教程 1/3” |
| 接触列表、传感器架、命令队列 | 清单式目标 |
| 通信、文书、内部报告 | 阶段完成横幅、过关动画 |

- 目标使用任务语言：`任务：阻止接管 / 第七号令 · Chronos`。
- 教程只通过副官建议与手册出现；不做弹窗教程。
- 玩家不知道“第几拍”，只知道窗口还剩多久、谁在做什么。

---

## 3　作者侧结构

- **Act** 用于任务/战役结构：Act 1 · Meridian、Act 2 · Solstice / L2。
- **Phase** 用于设计、测试与埋点：Phase 1 读、Phase 2 令、Phase 3 赌。
- 两者只存在于文档、代码状态机、调试输出；HUD/叙事不显示。
- 状态机可以继续驱动事件时序，但 UI 不读 `phase_label`；HUD 只读目标、窗口、接触、命令。

---

## 4　第一关

- **大目标**：阻止清算者完成对 Chronos 储罐与航道的接管，避免交火。
- **玩家自由**：卡位、撤人、取证、谈判、拖时间、开火；没有“正确阶段”。
- **默认不交火**：开火是灾难分支，不是常规玩法。
- **结局**：HOLD / EVACUATE / EXPOSE / FIRE（灾难）。
- **报告**：OCJC / OCUVF 内部事后报告，不是给 UEG 的报告。

---

## 5　实现清理

- HUD 不显示 `Phase 1/2/3`、`Act 1`、关卡、教程提示。
- `phase_label()` 只返回内部短名或不使用；不上屏。
- 目标从 `data/scenario_l1.json` 的 `objective` 字段读；不读 Act/Phase。
- 通信、报告里不出现“阶段/关卡/教程”等作者词。
- 这些属于文本审批范围；先列进 [`17_文本审批流程.md`](17_文本审批流程.md) 批次。
