# 真实空间系统与信息作战架构

> 本文件是 V17 下一阶段的总架构约束。目标不是继续用线条脚本“演”物理，而是让真实几何、轨道、传感器、损管和电子战成为同一套可操作机制，同时保持 V1 HUD 的视觉语言。

## 0　不可破坏的约束

- **视觉**：V1 HUD/plot 的四区、字号、密度、1px 线框、薄荷绿/琥珀色板；新增模型也只能用线框/低模/终端标注表达，不引入 V2 式大留白页面。
- **分层**：`core`（权威数据/状态）→ `sim`（物理/传感器/EW）→ `ui`（只读 view-model）。
- **单一权威**：一旦切换真实物理，轨道、站体、传感器等级、损管、EW 都必须只有一个来源，不允许 V15/V2 双套判定并存。
- **可回退**：切换开关与旧 demo 并存；任何阶段都必须可启动、可截图、可回归。

## 1　空间与轨道层

### 1.1 坐标系

- 地月惯性系（Earth-centered inertial, ECI）作为积分系；显示时转地月旋转系/局部 LVLH。
- 每个实体有：位置/速度、质量、姿态、角速度、有效面积、RCS、传感器/武器/对接端口。
- 站体/储罐有固定轨道根数或状态向量，不再用固定屏幕坐标。

### 1.2 物理

- 第一阶段：地球 + 月球 + 太阳第三体摄动 + RK4 积分；真实星历可用 JPL DE 简化表或解析月球轨道。
- 第二阶段：地月 CR3BP/星历混合；L1–L5 站保持推进（低推力/脉冲姿态控制）。
- 交会/对接：相对运动（Hill/Clohessy-Wiltshire 或数值积分）、接近走廊、相对速度/姿态约束、对接端口。
- 真实几何要在 V1 线框表达：轨道线、误差椭圆、接近走廊、对接锥、站体模块线框。

### 1.3 站体/舰船可见模型

- 站体：核心舱、储罐组、桁架、停泊港、散热板、通信桅杆；用低模线框/切面，不做贴图堆砌。
- 舰船：舰体、推进段、传感器桅杆、武器/光学窗口；可按舰级生成模块组合。
- 模型要有可交互挂点：传感器、对接端口、损管分区、武器/光学视轴。

## 2　损管/毁伤

### 2.1 结构

- 每舰 `damage_sections[]`：分区（舰体/动力/传感器/通信/推进/储罐/对接端口）、完整度、受损状态、火灾/失压/断电、维修难度。
- 命中/事故写入 `damage_events[]`：来源、方向、能量、穿透、后果。
- 子系统效果必须影响玩法：传感器失效、命令延迟、转向/Δv 限制、光学/雷达不可用、对接失败。

### 2.2 损管流程

- 检测 → 评估 → 分配维修队/资源 → 维修 → 恢复/降级/放弃。
- 损管队列有优先级、维修位、备件/电力/人员约束。
- 独立损管页：分区图、损伤时间线、维修队列、资源、后果预览；V1 线框。

### 2.3 接入顺序

先做 core/sim 完整状态与 probe；HUD 独立页；真实几何接入 V17 后再挂到命中/事故。

## 3　导航/交通管制/轨道机动

### 3.1 地月交通管制

- 站点/港口有进近航道、等待区、时间窗、优先级、ROE/交通规则。
- 交通管制是信息战的一部分：指令、许可、拒绝、伪装、延迟。
- 与通信/ELINT 联动：不合法机动会被对方交通管制/侦察发现。

### 3.2 导航与规划

- 航线：起点/终点/中转站/规避区/时间窗。
- 半自动规划：玩家选目标/约束，系统生成候选转移方案（Δv/时间/暴露/风险），玩家确认。
- 全自动机动：玩家授权后系统执行预设脉冲/连续推力，可中断。
- 战斗机动：保持/回避/接近/脱离/绕飞/姿态指向，带 Δv 预算和传感器暴露。
- 所有规划结果必须进入命令状态机，不直接改世界状态。

### 3.3 UI

- 独立导航页：地月系轨道图、目标/站点、时间轴、Δv 预算、方案对比、许可状态。
- V17 主 HUD 只保留摘要；压平态势资产迁入该页。
- 真实几何接入后，轨道线/接近走廊/对接锥在同一页显示。

## 4　传感器/光学/信息作战

### 4.1 统一传感器模型

- 唯一权威：球形雷达、TWS、光学、IR、IFF、ELINT、通信侦察都从同一实体/姿态/几何状态读取。
- 目标状态：未检测/方位/定位/分类/识别；身份与等级分离。
- 真实几何：地球/月球遮挡、光学视轴/视场、姿态、太阳光照、地球反照、热特征。

### 4.2 光学/IR

- 可见光：口径/焦距/曝光/凝视时间/相对角速度/光照；输出分类，不给身份。
- IR：热特征/背景/冷却；输出方位/距离档/热分类。
- 统一为一个光学/IR 通道管理器和独立通道窗；不再 V15/V2 两套。

### 4.3 IFF/ELINT

- IFF：模式/编码/询问-应答/欺骗/无应答；不明不自动判敌。
- ELINT：被动截获、信号指纹、测向；多站交叉定位作为进阶。
- 通信侦察与 ELINT 区分：通信内容与电子信号。

### 4.4 电子战/信息作战

统一模型包含：

- 探测/识别（传感器）
- 通信（链路、延迟、截获、欺骗）
- 电子战（干扰、压制、诱饵、假目标、静默）
- 指挥/命令（预命令、授权、延迟、拒绝）
- 舆论/取证/报告（第一关的政治信息战）
- 对抗效果必须进入同一事件/状态总线，不允许单独脚本。

- 独立 `cislunar_explorer` 和 `sensor_explorer` 是模型/几何验证台，不是游戏权威层。
- 后续任何模型必须先有 probe，再进 V17；不在游戏里直接调演示脚本。
