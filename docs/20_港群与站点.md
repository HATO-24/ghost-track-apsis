### 1.1　港群政治倾向

- **L1 Meridian**：立场摇摆。UEG 与 OCU 共管，港内同时存在两套行政与安保体系。
- **L2 Karman**：总体偏向 UEG；港群内部对 UEG 接管存在不安，担心“临时托管”长期化。
- **L3 Alborada**：OCU 稳定票仓，对 UEG 与清算者部队态度明确。
- **L4 Anvil**：OCU 最核心集群，坚定的殖民地自治支持者；ID13 的后勤依赖此地。
- **L5 New Lagos**：属于 OCU，但鹰派与鸽派斗争激烈；鹰派倾向模仿 MIDA 的袭扰策略，鸽派主张谈判争取自治。

### 1.2　月面与远地

- **月面永久居住领地-永昼 / Solstice**：月面地下多层级巨型城市，由多家企业组成的统筹理事会管理；UEG 在近地轨道外唯一登记在册的大型船坞 **新维多利亚 / Neo-Victoria** 位于月面。
- **远地环带飞地 / Distant Zonal Enclave**：小行星带工业集群，UEG 法律不承认其存在合法政治实体；唯一大型实体为 **外环合作社 / Outer Ring Cooperative**，是 ID13 最可能也最不可靠的补给来源。

## 6　设施层级、识别码与应答机（第二阶段追加）

> 性质：新增设定提案，与 `docs/42_legacy迭代记录.md` 同步。原文保留。

### 6.1 层级

港群不是单一空间站，而是“港群 → 设施 → 模块/泊位/储罐”的集群：

```text
L1 Meridian（港群 cluster）
├─ L1-01 Greenwich（行政/海关站）
├─ L1-03 Sextant（转运/进港调度站）
├─ L1-05 Chronos（燃料加注站 + 储罐群）
├─ L1-08 Astrolabe（商业/仲裁站）
├─ OTC-L1-01（轨道交通管制雷达卫星）
├─ TANK-L1-05-01..03（Chronos 储罐）
└─ PRT-L1-05-A/B（港口泊位）
```

物理层中，港群、空间站、OTC 卫星、独立储罐都是实体；泊位/对接口是设施的子对象。

### 6.2 识别码规则

| 类型 | 前缀 | 示例 |
| --- | --- | --- |
| 港群 | `CL-` | `CL-L1-MER` |
| 空间站/港口站 | `STN-` | `STN-L1-01` |
| 加注站 | `FUL-` | `FUL-L1-05` |
| 储罐 | `TNK-` | `TNK-L1-05-03` |
| OTC 卫星 | `OTC-` | `OTC-L1-01` |
| 泊位/对接口 | `PRT-` | `PRT-L1-05-A` |
| 中继/通信节点 | `RLY-` | `RLY-L2-02` |

应答机码独立于设施码：

```text
TP-CL-L1-MER
TP-STN-L1-01
TP-FUL-L1-05
TP-TNK-L1-05-03
TP-OTC-L1-01
TP-PRT-L1-05-A
```

规则：

- 每个实体唯一；不允许复用/回收后重新分配。
- 应答机类型字段必须返回 `station/port/fuel/tank/otc/relay`，不是泛化的“contact”。
- IFF/光学/ELINT 只能把应答机识别为 L4 证据；不能因“应答机是空间站”自动判友/敌。
- 无应答、错误码、缴获码、过期码：保持未知，不自动判敌。
- 港口/加注站/储罐/OTC 卫星均可独立被识别，不必先识别整个港群。

### 6.4 物理参数

每个设施至少：

```text
orbit: frame, epoch, r/v 或轨道根数, station_keeping, period_s
mass_kg, radius_km, cross_section_m2, attitude_quat
```

- 空间站/港口站：station-keeping，等效刚体。
- OTC 卫星：真实轨道，可被光学/雷达观测。
- 独立储罐：随站体或独立轨道。
- 对接口/泊位：设施子对象，暂不做独立碰撞体。
- 空间站内部结构、储罐热力学、详细碰撞：后续阶段。

## 7　轨道交通管制、OTC 卫星、燃料设施与航道记录（第二阶段追加）

- OTC 是独立设施实体，有应答机、设施码、物理参数；不是 UI 图标。

### 7.2 燃料储罐与加注设施

每个空间港/港群至少配置：

- 燃料储罐（`TNK-`）
- 加注站/加注接口（`FUL-`）
- 储罐区交通管制节点
- 事故隔离区/消防/泄压能力

L1 Chronos 仍为序章重点；其他港群的储罐/加注站按同等结构建数据，后续剧情可复用。

### 7.3 轨道交通管制机制

```text
OTC 监视
→ 航迹/应答机/设施码校验
→ 航道/泊位/窗口分配
→ NPC 船只占用航道
→ 玩家/敌方申请或伪装
→ 记录/异常/取证
```

- 航道有容量、方向、时间窗、优先级。
- NPC 船只按时刻表/合同占用航道；不是纯背景。
- 玩家/敌方单位可：
  - 申请合法航道
  - 伪造应答机/设施码
  - 改写/删除航道记录
  - 利用记录缺口掩盖行踪
- 伪装不是无代价：OTC 交叉校验、应答机异常、时间戳/轨迹不一致会产生 GHOST TRACK 线索。
- 航道记录进入 OTC/港务/黑匣子数据，可供调查/谈判/报告使用。

### 7.4 数据要求

- 设施表补 OTC/储罐/加注设施。
- OTC 轨道/数量进入物理层等效实体。
- 航道表：lane_id、端点、容量、窗口、方向、优先级、占用者。
- 记录：track_id、transponder、facility_code、clearance、handoff、edit/delete flags。
- 玩家/敌方伪装：`record_disguise` 状态 + 被识破概率/线索。
