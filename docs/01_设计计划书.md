## 0　一句话

> 你是一支轨道舰队的指挥官。你不能直接操船，只能下达命令；
> 你看到的一切都是**传感器和下属汇报**拼出来的，而它们都是滞后的、残缺的、可能被欺骗的。
> 你的胜负取决于：在信息不完整时，敢不敢下注。

## 1　玩家幻想

不是"我要开飞船"，而是「**我是那个在昏暗指挥舱里盯着接触列表决定谁去死的人**」。

具体到操作层面，玩家的三个动作是：

1. **读图** —— 判断哪些接触是威胁，哪些是诱饵
2. **分配** —— 把有限的传感器、火力、机动余量分给各个威胁
3. **下注** —— 提前下令，赌对方下一步

对应地，玩家**不会**做的事情：

- 不会手动飞行（没有摇杆飞行）
- 不会微操单舰的朝向（命令层面控制）
- 不会建造、不会经营（至少 v1 不做）

---

## 2　核心循环

| 时间尺度 | 玩家在做什么 |
| --- | --- |
| **秒级** | 读接触列表，切换传感器模式，指定优先级 |
| **分钟级** | 下令转移、开火、干扰；处理命令延迟带来的"命令过时" |
| **局级（20–40 分钟）** | 决定交战 / 脱离 / 补给；在 Δv（燃料）耗尽前结束战斗 |

**循环的张力来源**：你的每一条命令都要**几秒到几十秒**才生效，而你看到的画面本身就是**几秒前**的。所以你永远在打一场"过去的战争"。

## 3　世界与尺度

### 3.1 战场设定

**地球轨道 + 地月空间**（近未来）。理由：

- 引力参数、轨道速度都是真实可查的，玩家可以用直觉学习
- 轨道周期 90 分钟量级，机动窗口天然形成节奏
- 不需要行星际尺度的大数，UI 好做

### 3.2 关键决策：轨道是**真的**

不做"太空里的二战海战"（船停着对轰）。做真实开普勒轨道：

- 所有舰船沿真实轨道运动，交战双方在**不同的轨道平面**
- 交会需要真实机动，**不是走到一起就能打**
- 交战窗口很短：相对速度通常 1–10 km/s，接触时间以秒计

这带来一个别人很难抄的特征：**"位置"不是坐标，是轨道**。同样的距离，顺行接近和逆行接近的代价差一个数量级。

### 3.3 时间加速

真实轨道周期 90 分钟，必须有时间加速。

- 1× / 10× / 60× / 300× 四档
- **事件自动降速**：新接触、导弹发射、损管报警时自动掉到 1×
- 加速时命令仍然生效，但延迟按**仿真时间**累计

## 4　舰船与操纵（牛顿力学）

### 4.1 六自由度刚体

每艘船是一个刚体：位置、速度、姿态（四元数）、角速度。推进与 RCS 产生力与力矩。

**这一条决定了游戏的手感**：船不会"停"，只能"改变轨道"。所谓机动，就是**在正确的时间、朝正确的方向、烧掉正确的 Δv**。

### 4.2 三种推进

| 类型 | 比冲 Isp | 推力 | 用途 |
| --- | --- | --- | --- |
| 化学 | 320 s | 高（0.5–3 g） | 战术机动，几秒到几十秒的脉冲 |
| 核热 | 900 s | 中 | 战役转移 |
| 电推 | 3000 s | 极低（0.001 g） | 长期轨道调整，连续烧几百秒 |

**燃料 = Δv**，这是本作最重要的资源（见第 11 章）。

### 4.3 姿态

姿态不是装饰：**主炮朝向决定能不能开火**，**装甲朝向决定挨打时伤在哪**。

RCS 转动有角速度上限和角加速度，转 90° 需要几秒。所以"发现目标 → 转向 → 开火"本身就是一段需要预判的时间。

## 5　传感器

### 5.1 三种传感器

| 类型 | 给出 | 代价 |
| --- | --- | --- |
| **被动红外** | 方位 + 强度（可推算距离，误差大） | 无。但对方**开推进时**信号暴涨 |
| **主动雷达** | 距离 + 方位，精度高 | **暴露自己**：对方立刻获得你的方位 |
| **光学** | 纯方位 | 需要多平台交叉才能定位 |

**核心规则：开机就是暴露，开推进就是点亮自己。**

这一条把"电子对抗"变成自然发生的博弈，而不是附加系统。

### 5.2 接触等级（L0–L4）

| 等级 | 含义 | 玩家能做什么 |
| --- | --- | --- |
| **L0** | 无接触 | — |
| **L1** | 有回波，方位不定 | 派传感器去确认 |
| **L2** | 定位，但**舰种未知** | 判断威胁大小 |
| **L3** | 分类完成（护卫/巡洋/补给） | 分配火力 |
| **L4** | 识别到具体舰名 | 知道它的武器与弱点 |

**等级会衰减**：失去跟踪后，L4 会逐级退回 L1。这就是"记忆"系统——不是消失，是变模糊。

### 5.3 探测概率

```
SNR = P_tx · G_tx · σ · G_rx / ( (4π)³ · R⁴ · kTB )   ← 雷达方程（简化）
Pd  = 1 / (1 + exp(-k·(SNR_dB - SNR₀)))                ← 逻辑斯蒂曲线
```

工程上不需要玩家看到这个公式，但它决定了：

- 距离翻倍，探测概率急剧下降（R⁴）
- 目标雷达反射面积 σ 决定"谁先被看见"
- 干扰的本质就是抬高噪声底、降低 SNR

## 6　电子战

三个层次，从"烦人"到"致命"：

### 6.1 噪声干扰
抬高对方接收机噪声底 → 有效探测距离缩短。
**代价**：干扰机自己是个巨大的辐射源，**等于举着火把**。

### 6.2 欺骗干扰（重点）
生成**假接触**。玩家会在雷达上看到不存在的舰队。

- 假接触有细微特征：信号强度与距离的关系不对、机动不符合物理
- **多传感器交叉验证**可以剔除：用另一个方向的被动传感器看同一方位
- 高级玩法：**用假目标引诱对方开火**，暴露火力位置

### 6.3 通信干扰
切断你与下属的链路 → **命令延迟暴涨**（见第 7 章）。
这是最恐怖的一种：你还在指挥，但你的命令要 40 秒才能到。

## 7　指挥链与命令延迟（本作的核心机制）

### 7.1 你不操船，你下命令

```
命令 = {
  目标单位, 动作类型, 参数, 下达时刻
}
```

命令**不是即时生效**的：

```
生效时刻 = 下达时刻 + 传播延迟 + 执行准备时间
```

| 链路 | 传播延迟 | 抗干扰 |
| --- | --- | --- |
| 激光通信（直接，需视线） | 0.3–2 s | 主链路；高带宽；被遮挡就断 |
| 激光中继（中继舰） | 8 s | 无中继时 45 s；中继损失后回退 |
| 无线电 | 2–8 s | 第三手段；易被干扰/截听 |
| 红外信息传输 | 2–8 s | 低带宽短报文；第四手段 |
| 可见光传输 | 秒级–分钟级 | 最后手段；极低带宽；手动操作 |

### 7.2 命令队列可见

玩家能看到"这条命令还有 6 秒生效"，并且**在生效前可以撤销**。
这创造了一个很特别的紧张感：你已经下了命令，但还有几秒钟可以后悔。

### 7.3 通信质量差 → 命令可能被误解

低质量链路上，命令有概率被执行成"近似动作"（比如"转向 090"被执行成"转向 110"）。
玩家会在事后从汇报里发现不对劲。

## 8　武器与交火

### 8.1 三类武器

| 武器 | 特性 | 对抗方式 |
| --- | --- | --- |
| **轨道炮** | 瞬时命中，但需要**精确对准**；后坐力会给自舰一个 Δv | 机动规避（提前量） |
| **导弹** | 有飞行时间，可被拦截；自带 Δv，能追击 | 近防炮、诱饵、机动耗尽它的 Δv |
| **近防炮** | 拦截来袭目标 | 饱和攻击 |

### 8.2 交火几何

相对速度决定一切：

- 高相对速度 = 交火窗口只有几秒，但**一发就能重创**
- 低相对速度 = 可以长时间缠斗，但双方都能从容拦截

**玩家要做的决策**：是拉高相对速度做一次"掠袭"，还是压低相对速度打消耗战？
这两种选择对应的 Δv 代价完全不同。

### 8.3 命中与损伤

命中后按**命中部位**决定损伤：

- 正面 → 装甲吸收
- 侧面 → 传感器/火控损伤
- 背面 → 推进/反应堆

---

## 9　损伤与损管

分系统损伤，不是血条：

| 系统 | 受损后果 |
| --- | --- |
| 传感器 | 接触等级下降，看不到远处 |
| 火控 | 无法解算射击诸元 |
| 推进 | Δv 余量减少，机动受限 |
| 通信 | 命令延迟增加 |
| 反应堆 | 全系统降级 |

**损管是资源分配问题**：三个系统同时着火，你先修哪个？

---

## 10　资源

| 资源 | 作用 | 稀缺度 |
| --- | --- | --- |
| **Δv（燃料）** | 所有机动的代价 | 极稀缺，决定能打多久 |
| 弹药 | 轨道炮/导弹 | 稀缺 |
| 冷却剂 | 连续开火会过热 | 中等 |
| 备件 | 损管消耗 | 中等 |

**Δv 是本作的经济系统**。一次鲁莽的机动可能让整支舰队失去脱离战场的能力。

## 11　信息架构（我们最强的部分）

这是 DIIT 项目已经验证过的东西，直接迁移：

### 11.1 共形 HUD
符号贴在世界坐标上，线宽与字号不随距离变化（真实 HMD 做法）。

### 11.2 接触列表 + 记忆衰减
每个接触有：批号、等级、方位、距离、相对速度、最后更新时刻。
失去跟踪后**不是删掉**，而是标记为"陈旧"并逐级降级——玩家要自己判断这条信息还能不能信。

### 11.3 命令面板
不是右键菜单，而是**队列**：能看到已下达、未生效、已执行的命令。

### 11.4 时间轴
可以回放最近 60 秒的态势，看清楚"当时我为什么那么判断"。

## 12　视觉方向

**延续 DIIT 的线框语言**，因为：

1. 我们的渲染管线就是干这个的（投影 / 遮挡 / 材质 / 后处理）
2. 线框天然适合"仪表读数"的观感
3. 成本可控：**所有几何都由代码生成**，不需要美术画

具体：深色背景 + 荧光绿线框 + 衍射后处理 + 高信息密度排版。

## 13　技术方案

### 13.1 阶段一：原生 Web（不上引擎）

理由：

- 本作 80% 是**界面与仿真**，不是 3D 画面
- 我们已有的渲染管线、HUD、后处理可以直接复用
- 零构建步骤，改一行刷新就看到
- 真需要 3D 舰船模型时再换 Godot，仿真层可以整体搬走

### 13.2 架构原则

```
sim/     纯数据与数学，无 DOM、无渲染
render/  只读 sim 状态，画出来
hud/     符号层，输入状态输出符号列表（与后端解耦）
input/   键鼠 → 命令
data/    舰船/武器/传感器 JSON
```

**铁律：仿真与渲染完全分离。** 仿真跑固定步长（比如 20 Hz），渲染可丢帧。

### 13.3 确定性

同样的初始条件 + 同样的命令序列 = 同样的结果。
这让我们能写**回归测试**：录一段命令，跑 60 秒，比对最终状态。

### 13.4 迁移清单（从 DIIT 项目）

| 资产 | 用途 |
| --- | --- |
| `src/math.js` | 向量/矩阵，扩展成 3D |
| `src/scene.js` 的渲染思路 | 投影 / 遮挡 / 材质管线 |
| `src/hud.js` | 共形符号、接触标记、班组面板 |
| 后处理 CSS | 衍射色散 / 抖动 / 扫描线 |
| `tools/capture.js` | 自动化截图（**但必须改成串行、可控、不堆积进程**） |

## 14　里程碑

### M0 · 物理原型（1–2 周）
**目标：证明"真实轨道 + 命令延迟"好玩**

- 一艘船，真实开普勒轨道
- 一个假想敌，一个传感器
- 下达一条"变轨"命令，看到它延迟生效
- 时间加速

**验收**：能看懂自己在哪、要去哪、还够不够 Δv。

### M1 · 交战原型（2–3 周）
- 两支小队，三种传感器，接触等级 L0–L4
- 轨道炮 + 导弹
- 命令队列与撤销

**验收**：一局 10 分钟内能分出胜负，且玩家说得清自己为什么输。

> 注（v0.2）：M1 先以 [`07_第一关_监督交接.md`](07_第一关_监督交接.md) 的教学切片为验收；
> 武器与电子战推迟到 M2，先把"读图 / 传感器架 / 命令延迟 / ROE"跑通。

### M2 · 电子战与垂直切片（3–4 周）
- 噪声/欺骗干扰，假接触
- 损管
- 完整视觉与音效占位

**验收**：给没玩过的人 15 分钟，能自己打完一局。

### M3 · 内容与打磨
- 更多舰种、任务、剧本
- 平衡

## 21　声望、报告与审裁

第一关的三种结局都算通关，分别写入阵营声望与剧情分支；详细系统见 [`08_声望与审裁.md`](08_声望与审裁.md)。

- **不做道德值**：只有阵营声望、上级信任、案卷。同一行为在不同阵营评价不同。
- **假报告**：只在出现不良后果后可选；多次造假累积 `perjury_count`，第二次审计，第三次触发战争罪 / 叛军 / 被新监督舰队追杀的结局。
- **开火**：允许；demo 自动停止并显示后果，后续审裁分支不在 demo 做。
- **demo 范围**：只记录 flags、案卷条目和报告卡；不做声望 UI、审判流程、新监督舰队。
