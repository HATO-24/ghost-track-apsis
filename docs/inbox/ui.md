## 3　V1 的设计理念（为什么是那样）

V1 的战术图是**一块斜放在指挥官面前的战术板**，不是星图。

1. **投影**：LVLH 局部水平面，斜俯视。距离环是椭圆，因为那是圆环在斜面上的投影；高度用垂线落到平面。
2. **符号**：接触是 track，不是船。L0–L4、误差椭圆、只有方位的楔形、幽影、命令幽灵；读的是“这条信息能不能信”。
3. **信息架构**：左读、中看、右算、底下令与后悔。四区对应四个动词。
4. **地球**：本来负责四件事——定“下”、遮挡、晨昏线（光学）、尺度。  
   **问题**：它被画成了实体风景，不是仪表。投影混用（俯视板 + 地平线视角）、语言不一致（线框 vs 明暗实体）、亮度和尺度倒置（最亮的参照压过信息）。  
   **修法**：不是删掉地球，是**降级成基准弧**，让它也遵守“仪表”规则。

### V1.5 的地球

- 1px 弧 + 少量刻度 + 4 层极薄大气辉光；
- 标签 `LOCAL HORIZONTAL / +400 km`、`EARTH REF · DATUM`（在图右下）；
- `SUN 312°` 用一个刻度表示，不画阴影；
- 没有实体填充，没有经纬网，没有晨昏明暗；
- 亮度低于选中接触；遮挡由 sim 标记，不靠背景图；
- 它仍然在画面底部，保留 V1 的构图锚点。

## 8　已知的坑（不要重踩）

1. **D 盘工作区不稳定**：并行会话会整体重置，文件会消失/截成 0 字节。不要以 D 盘为唯一副本。
2. **Godot `--path` 带空格**：必须加引号；参数用反斜杠路径更稳（正斜杠曾导致项目管理器）。
3. **截图不要等 `RenderingServer.frame_post_draw`**：之前会挂起；用 `process_frame` 计数 + `get_texture().get_image()`。
4. **SubViewport 1920 截图**：窗口要 borderless 1920×1080，否则 SubViewport 会被容器缩到 1600×900 裁边。
5. **`class_name` 缓存**：删过 `.godot` 后，直接用 `--path` 跑可能缺全局类；本工程已改成 `preload`，不依赖缓存。
6. **系统字体**：换机器可能缺 Consolas/微软雅黑；发布前打包字体。
7. **V2 占位厂名**：不要因为 V2 的菜单好看就把“远地点船坞/铁砧/北辰/白霜/静默”带回来，和设定书冲突。
8. **V1.5 没有相机**：别以为它已经支持旋转/压平；它只是 V1 的静态板 + 新动效。
9. **GIF 体积**：11.9MB 是 720×405/10fps 的结果；再大不适合聊天。
10. **启动遮罩**：boot 期间点击被 guard；没有 skip，用户可能觉得 1.7s 长。
