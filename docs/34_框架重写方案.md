# 框架重写方案（v2）

> 目标：把 `game_v15` 的“单关演示 + 绝对坐标 HUD”升级为可扩展到多实体、多舰种、多任务节点的数据驱动框架。
> 原则：保留成熟底层，重写框架层；旧版 `game_v15` 保留可运行，新框架放 `game_v16`。

## 0　保留

- `orbit_model.gd`、`sensor_model.gd`：轨道传播与传感器物理判定。
- `pal.gd`、`fonts.gd`、`crt.gdshader`：视觉语言。
- `audio/`：音乐/底噪/音效。


```json
{
  "id": "2001",
  "kind": "ship",
  "side": "hostile",
  "name": "AV-4412 传唤者",
  "name_en": "SUMMONS",
  "class": "传唤级",
  "role": "通报舰",

  "capabilities": ["sensor.elint.passive", "sensor.iff.interrogator", "comms.radio"],

  "orbit": {"frame": "L1", "r": [0, 0, 0], "v": [0, 0, 0]},
```

- `kind` 决定右栏 section；`capabilities` 决定动作、传感器架、命令可用性。
- 不写 `if batch == 2001`；空间站/储罐/残骸共用 `kind`、`orbit`、`radius`。

## 3　动作与能力

动作由 `content/actions/*.json` 定义，`available(actor,target,track)` 根据能力、距离、目标等级、ROE 返回可用/原因；UI 只渲染。

```json
{"id":"radar_illum","label":"雷达照射识别","requires":["sensor.radar.active"],
 "target_levels":["L1","L2"],"duration_s":2.0}
```

## 4　状态机

- 任务：`PRELUDE → READ → COMMAND → DECISION → CONSEQUENCE? → REPORT → END`，节点来自场景。
- 航迹：`UNKNOWN → BEARING(L1) → POSITION(L2) → CLASSIFIED(L3) → IDENTIFIED(L4)`。
- TWS：`SEARCH → DETECT → ACQUIRE → TRACK → STARE → FIRE_CONTROL`。
- 命令：`PRE_ORDER → AUTHORIZED → QUEUED → TRANSMITTED → EXECUTING → DONE / ABORTED / REJECTED`。
- 证据/副官：由能力、资源（穿梭机/通信）和阶段可用性决定，不写死四个选项。

## 5　UI 框架

- 统一 `ListView`：接触/命令/证据/事件虚拟滚动、选中、右键。
- 右栏 section registry：按 `kind/capabilities` 生成，超出高度滚动。
- 地图右键动作菜单由动作注册表生成；不可用显示原因。
- 布局使用 anchors/container，设计基线 1920×1080，16:9 letterbox，输入统一映射。

### 8.3　球形雷达 / TWS / 光学

- **球形搜索**：探测体是以平台为球心的球（全向，无方位/俯仰视场限制，**不画扇形**）。
  有效半径 `R_eff = range_km × (RCS/10 m²)^0.25 × 干扰因子`（05 §S-02 / §E-01）；
  `Pd = logistic(-40·log10(R/R_eff))`（01 §5.3）；稳定跟踪半径 = `track_range_km` 同式缩放
  （05 §S-02 的 15,000 / 30,000 km 两档）。刷新按 `refresh_s` 扫描；暴露按开机时长推进：
  ELINT 截获距离 = `range_km × 1.5`（LPI ×0.5），20 s（LPI 40 s）后可定位（05 §S-02）。
- **TWS 状态机**（每目标独立、可多通道，`max_channels` 默认 6）：
  `SEARCH → DETECT → ACQUIRE → TRACK → STARE → FIRE_CONTROL`。
  [本文定值] 阈值：连续 2 次检测 → ACQUIRE；3 次且 quality≥0.60 → TRACK；
  quality≥0.70 → STARE；STARE 驻留 `max(refresh_s, 8 s)` 且 quality≥0.85 → FIRE_CONTROL。
  quality 只在漏刷新后按 8 s 时间常数衰减；漏刷新 → 掉回 TRACK（`fire_control_lost`），
  13 s 未更新 → `lock_lost` 降级到 DETECT，30 s 未更新且 quality<0.1 → 释放通道。
  通道满时按 `quality × (2 − R/R_eff)` 淘汰最弱通道；每通道输出 quality / age /
  update_rate_hz / hits / misses / stare 进度 / fire_control 解算 / 状态历史。
- **光学/IR 凝视**（与 TWS 独立，互不引用）：通道 `idle → acquiring → staring → locked`，
  条件丢失 → `lost`（保留进度 8 s）。可见光需 `sun_illum ≥ illum_min`（阴影区不可见），
  所需凝视 = `clamp(40 s × (R/8,000 km)², 4 s, 240 s)`（05 §2.1），自舰机动 >
  `reset_maneuver_g` 则凝视归零重来；锁定支撑 L3 分类（只给舰级，不给身份）。
  IR 锁定时间为 [本文定值] 4 s，只支撑 L1 + 远/中/近距离档，不给距离解。
  光学/IR 都输出 `measured_range_km = -1`（不伪造测量）；`slant_range_km` 仅几何距离供显示。

### 9.2　关键机制

- **航迹等级**：观测带支撑级 S 时刷新 1..S 的证据时间戳；`level_from_evidence(now)` 按
  `valid_s` 逐级衰减、L1 为记忆地板（失去跟踪不删除）。支撑级一致性校验：声称 L2 无位置→降 L1、
  L3 无分类→降 L2、L4 无身份/IFF→降 L3；`quality < min_quality` 不刷新证据。
- **身份与等级分离**：`track.identity_kind`（七级：pending/unknown/assumed_friend/friend/neutral/
  suspect/hostile）独立更新；IFF 无应答→unknown（不自动判敌）；身份变化不影响等级。
- **不写死批号**：航迹 id 来自内容（"2001"）或自动分配（`T0001`）；`entity_id` 关联真实实体，
  虚警/纯方位回波可以只有航迹（9002 迁移后 `has_entity=false`）。
- **动作数据驱动**：动作定义、所需 capability、允许等级集合、距离上限、阶段/flag 前置都在
  `content/actions.json`；不可用时 `reason` 必填，UI 直接显示。
- **命令**：`world.issue_order()` 先做动作可用性校验（不可用直接拒绝、不建命令）；
  预命令创建后 `world.t` 不变、不入队；`world.advance(dt)` 推动队列与航迹衰减。
- **阶段数据驱动**：阶段数量/顺序/进入条件/提示文本全部来自场景；V2-1 只定义机制与 flag 名，
  剧情置位（`prelude_executed`/`decision_open`/`decision_made`/`report_submitted`/`fire_release`）
  留给后续关卡流程；第一关结局（HOLD/EVACUATE/EXPOSE/FIRE）来自 `story.endings` 内容，代码不写死。

### 9.5.1　实现

- **perform_action**（`core/world.gd`）：7 个支持动作（crossfix/radar_illum/model_ident/
  radar_track/iff_query/optical_channel/ir_channel）→ 观测/状态；可用性仍走 `content/actions.json`
  + `V2Actions.available_one`；观测用动作 effect 支撑级 + 目标真实轨道几何 + 平台传感器参数
  （`SensorModel` 型号库），本舰能力不足时自动选舰队内可执行的友军平台（IFF 由远地点执行）；
  每个成功动作在命令队列留一条 DONE 审计记录；返回 `{ok,action,level,level_name,identity,
  actor_id,actor_name,reason,reason_code,detail,order_id,...}`。武器类显式 `unsupported`。
  **不伪造 L4**：IFF 仅友方给 L4；无应答只到未知/可疑。
- **PRELUDE**：`prelude_choose_route/window/confirm/execute/skip` + `vm_prelude()`；数据来自
  `story.prelude`（routes/windows/confirm/execute/done_comm）；执行前置 `prelude_executed`，
  执行前世界时间冻结（`advance` 返回 `frozen=true`）。自动化钩子 `DSH_SKIP_PRELUDE=1`。
- **证据任务**：`start_evidence(id)`（穿梭机互斥、远程可并行）/ `advance_tasks(dt)` /
  `evidence_remaining` / `vm_evidence()`（remaining/progress）；完成效果来自
  `evidence.items[].flags_on_done`（evacuation → `civilians_evacuated`）。
- **决策/报告/END/RESTART**：`open_decision()` + `vm_decision()`（EXPOSE 证据不足 enabled=false）、
  `choose_ending(HOLD/EVACUATE/EXPOSE/FIRE)`（EXPOSE 需 can_expose；FIRE 置灾难）、
  `submit_report(truth)`（伪造置 audit_flag/audit_count，文本优先 `story.report_fake`）、
  `end_summary()`、`restart()`（场景 clone 重载 + mission.reset）。
- **自动时间线**：`advance(dt)` 触发 `story.events`/`radio_lines`（各一次，event kind=`timeline:<type>`），
  `type="decision"` 自动打开决策；证据任务到期完成;命令队列/航迹衰减/mission 自动推进一格
  （`mission_auto` 可关）；**不自动做玩家识别动作**（教学门控）。
- **mission 联动**：`attach_mission` 后 flow flag（prelude_executed/decision_open/decision_made/
  fire_release/report_submitted/audit_flag/civilians_evacuated）自动同步给 `V2Mission.set_flag`；
  `phase_context` 跟随 mission.kind；`mission_snapshot()` 提供 UI。
- **view-model**：`vm_flow/vm_prelude/vm_decision/vm_report/vm_end`；`vm_state()` 增
  prelude/decision/report/ended/time_frozen/audit_flag；`vm_evidence()` 增 remaining/progress。
- **内容**：`content/scenario_l1_v2.json` 的 evacuation 加 `flags_on_done`；
  `content/story_l1.json` 增 `story.fire_option`（FIRE 灾难分支选项）。schema 未变。
