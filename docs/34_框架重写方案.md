# 框架重写方案（v2）

> 目标：把 `game_v15` 的“单关演示 + 绝对坐标 HUD”升级为可扩展到多实体、多舰种、多任务节点的数据驱动框架。
> 原则：保留成熟底层，重写框架层；旧版 `game_v15` 保留可运行，新框架放 `game_v16`。

## 0　保留

- `orbit_model.gd`、`sensor_model.gd`：轨道传播与传感器物理判定。
- `pal.gd`、`fonts.gd`、`crt.gdshader`：视觉语言。
- `audio/`：音乐/底噪/音效。
- 第一关文本与 `scenario_l1.json` 作为迁移来源。

## 1　分层

```
game_v16/
  core/       纯数据/状态机，不引用 UI
    entity.gd       实体 record
    scenario.gd     场景加载/校验
    world.gd        世界状态、选中、图层
    tracks.gd       航迹/识别状态机 L1–L4 + TWS
    actions.gd      能力→动作注册表
    orders.gd       预命令→授权→队列→执行
    mission.gd      任务阶段状态机
    events.gd       事件总线
  sim/        既有物理/传感器数学适配 + TWS/雷达模型
  ui/         只消费 view model
    app.gd          启动/屏幕路由
    layout.gd       设计基线/letterbox
    theme.gd        色板/字号/间距 token
    widgets/        list_view / scroll_view / section / menu / modal
    views/          tactical / tracks / unit / orders / comms / decision
  content/      entities / scenarios / actions / texts
```

依赖方向：`ui → core`；`core` 不引用 `ui`。

## 2　实体 schema

```json
{
  "id": "2001",
  "kind": "ship",
  "side": "hostile",
  "name": "AV-4412 传唤者",
  "name_en": "SUMMONS",
  "class": "传唤级",
  "role": "通报舰",
  "faction": "UEG 第33舰队",
  "capabilities": ["sensor.elint.passive", "sensor.iff.interrogator", "comms.radio"],
  "signatures": {"radar": "YW-R9", "iff": "MK-12"},
  "orbit": {"frame": "L1", "r": [0, 0, 0], "v": [0, 0, 0]},
  "ui": {"badge": "hostile", "icon": "triangle"}
}
```

- `kind` 决定右栏 section；`capabilities` 决定动作、传感器架、命令可用性。
- 不写 `if batch == 2001`；空间站/储罐/残骸共用 `kind`、`orbit`、`radius`。

## 3　动作与能力

动作由 `content/actions/*.json` 定义，`available(actor,target,track)` 根据能力、距离、目标等级、ROE 返回可用/原因；UI 只渲染。

```json
{"id":"radar_illum","label":"雷达照射识别","requires":["sensor.radar.active"],
 "target_levels":["L1","L2"],"duration_s":2.0}
```

## 4　状态机

- 任务：`PRELUDE → READ → COMMAND → DECISION → CONSEQUENCE? → REPORT → END`，节点来自场景。
- 航迹：`UNKNOWN → BEARING(L1) → POSITION(L2) → CLASSIFIED(L3) → IDENTIFIED(L4)`。
- TWS：`SEARCH → DETECT → ACQUIRE → TRACK → STARE → FIRE_CONTROL`。
- 命令：`PRE_ORDER → AUTHORIZED → QUEUED → TRANSMITTED → EXECUTING → DONE / ABORTED / REJECTED`。
- 证据/副官：由能力、资源（穿梭机/通信）和阶段可用性决定，不写死四个选项。

## 5　UI 框架

- 统一 `ListView`：接触/命令/证据/事件虚拟滚动、选中、右键。
- 右栏 section registry：按 `kind/capabilities` 生成，超出高度滚动。
- 地图右键动作菜单由动作注册表生成；不可用显示原因。
- 布局使用 anchors/container，设计基线 1920×1080，16:9 letterbox，输入统一映射。
