## 0　一句话

> 清算署不是「另一支海军」，它是**带着军队的法务机构**。
> 所以它的船必须同时有**海军身份**和**案卷身份**；现在的问题是只显示了后者，前者被吞掉了。

---

## 1　为什么用案卷号

- 清算署的权力来自**裁定**，不是来自主权。它没收一条船、执行一次接管，都必须挂在一个案子上；案卷号是它的**法律身份证**。
- 被没收的船保留原厂型号和旧舰名，但法条带下面盖着旧名字；新刷上去的是**案卷号 + 执行舰身份**。这是 04 §11.4/§11.5 的设定，也是「船有名字，人有编号」的反面：**对清算署来说，船首先是一个案子**。
- 但案卷号不该是**唯一的身份**。一艘正规军队的船，首先应该有：
  - **舰级 / class**
  - **舰种 / type**
  - **舰名 / name**
  - **舷号 / hull number**
  - 案卷号只是**法条带上的附加注记**，像战利品登记号。
- 现在 UI 把「案卷 4471」当主标识，读者会以为这是船名或舷号——这就是你看到截图时的困惑。**错不在案卷号，错在层级。**

---

## 2　为什么「传唤级」还在

- 03 §8.3/04 §11.4 的六个「舰级」——清算、执刑、禁制、追索、征用、传唤——其实是**任务职能/教条**，不是舰种。
- 「传唤级」作为职能是成立的：清算署确实需要一条**送达/联络**的船，最客气的一级。
- 但它作为**舰级**不成立：正规军队不会把「送达」当成一个舰种；它应该是一条**通报舰 / aviso**，任务是传唤/送达。
- 结论：**保留「传唤」作为任务职能，补上正式的舰种**：
  - `传唤级通报舰` / `传唤级 · 通报舰（aviso）`
  - 而不是让「传唤级」单独承担舰级 + 舰种 + 职能三件事。

## 3　建议的三层身份

| 层 | 是什么 | 谁定 | 例 |
| --- | --- | --- | --- |
| **舰级 / class** | 正式舰级名，按法律/机构/传统命名 | 清算署海军条令 | 清算级、执刑级、禁制级、追索级、征用级、传唤级 |
| **舰种 / type** | 舰体规模与战术角色 | 海军条令 | 战列舰、重巡洋舰、轻巡洋舰、驱逐舰、护卫舰、通报舰 |
| **任务职能 / role** | 这次任务在干什么 | 特遣群/法院 | 清算、执刑、禁制、追索、征用、传唤 |
| 附加 | 舰名 + 舷号 | 海军/登记处 | 湮没者，舷号 4471 |
| 附加 | 案卷号（法条带） | 清算署 | 案卷 4471 |

**示意：**

- `执刑级重巡洋舰 · 湮没者 · 舷号 4471`
  法条带：`案卷 4471`
- `传唤级通报舰 · 舷号 023`
  法条带：`案卷 4471`
  （第一关在斛送达通知的那条船；案卷 4471 是它送的通知，不是它的舷号。）

## 4　建议的清算署舰级表

| 舰级 | 舰种 | 任务职能 | 定位 |
| --- | --- | --- | --- |
| **清算级** | 战列舰 | 清算 / 主力 | 机构本身命名，最常见的主力 |
| **执刑级** | 重巡洋舰 | 执刑 / 旗舰 | 出现即意味着终局 |
| **禁制级** | 轻巡洋舰/封锁巡洋舰 | 禁制 | 断航、驻留 |
| **追索级** | 驱逐舰 | 追索 / 登舰 | 追击、跳帮 |
| **征用级** | 护卫舰/回收舰 | 征用 | 缴获、回收 |
| **传唤级** | 通报舰（aviso） | 传唤 / 送达 | 最客气的一级；第一关的送达舰 |

- 舰级名可以继续用「法律动作」，这没有问题——现实海军也用人物/地名/战役命名舰级；问题是**舰种必须单独存在**。
- 舰名池、舷号段、日文读音沿用 04 §11；只在身份显示上增加「舰种」。

## 5　玩家与敌人的识别对比

| | 公约 / 玩家 | 清算署 |
| --- | --- | --- |
| 舰体来源 | 买、改装、用坏；型号 + 「改」 | 没收、标准化改装、统一涂装 |
| 身份 | 型号 + 舰名 + 舷号；没有正式舰级 | 正式舰级 + 舰种 + 舰名 + 舷号 + 案卷号 |
| 视觉 | 拼装、不对称、补丁、不同厂 | 标准、对称、批量、法条带 |
| 命名 | 舰名委员会按系列授予 | 舰级 = 教条；舰名 = 后果 |
| 读法 | 「这是哈马丹，托盘-5 改，舷号 114」 | 「这是执刑级重巡洋舰，湮没者，舷号 4471，案卷 4471」 |

- 玩家舰队是**拼装的特遣群**；敌人是**标准化的机构舰队**。这正是 Nebulous 式的区分：不是靠颜色，是靠**编制语言**。
- 敌舰在接触列表里应该先读舰级/舰种，再读舰名/舷号，最后才是案卷号（法条带小字）。玩家舰则读型号/舰名/舷号。

---

## 6　与 Nebulous 的对照

- Nebulous 的船有**舰体/舰级**、**角色（frigate/destroyer/cruiser 等）**、**阵营设计哲学**；玩家靠识别这些来读战场。
- 我们现在的六「舰级」把 role 当成了 class，等于 Nebulous 里把「missile frigate」直接当舰级；读起来像职能表，不像海军。
- 修正后：
  - **class**（清算级/执刑级…）→ 正式舰级；
  - **type**（战列舰/重巡/驱逐舰/通报舰）→ 舰种；
  - **role**（清算/执刑/禁制/追索/征用/传唤）→ 任务；
  - 玩家：型号 + 改 + 舰名 + 舷号；敌人：class + type + name + hull + docket。

## 7　为什么第一关用「三拍」而不是 Scene 1/2/3

- **三拍**是**教学/剧作**术语：一拍一个功能（读 → 令 → 赌），不是三个场景。
- 第一关只有一个连续场景：**环一 · 斛，交接执行窗口**。三个人物/动作都发生在同一地点、同一段时间里；把它切成 Scene 1/2/3 会暗示三次换场，实际没有。
- 建议的写法：
  - **第一场 / SCENE 1 · 斛**：整个第一关；
  - **第一拍 / BEAT 1 · 读**、**第二拍 / BEAT 2 · 令**、**第三拍 / BEAT 3 · 赌**：场内的三个教学节拍；
  - UI 可显示 `阶段 1/3` 或 `BEAT 1/3`，不写 Scene 1/2/3。
- 如果你更喜欢影视术语，可以改成 **Setup / Confrontation / Resolution** 或 **Act 1/2/3**；但「三拍」在设计和验收时更好用，因为它直接对应玩家要学会的三件事。

## 8　建议改动

1. `04 §11.4/§11.5`：给六个舰级补 **舰种** 列；传唤级 → 传唤级通报舰。
2. `03 §8.3`：舰级表补舰种；明确「舰级 = 教条，舰种 = 海军条令，职能 = 任务」。
3. `07 §2`：第一关接触显示改为 `传唤级通报舰 · 舷号 023`，法条带小字 `案卷 4471`；不再用「案卷 4471」当唯一 ID。
4. `10/12`：补「舰级/舰种/职能」术语；案卷号定义为法条带注记。
5. `scenario/UI`：接触列表优先显示 class + type + name/hull；案卷号放副行/法条带。
6. `01/07` 的「三拍」保留；章节标题改为「第一场 · 斛 / 三拍」。
