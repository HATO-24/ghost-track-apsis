## 0　任务与原则

### 0.1 任务

07 §1 的四条主要教学目标：

1. **基础轨道航行操作**：母港 L4-02 交接 → 设定目的地 → 变轨窗口 → 下令 → 抵达 L1 入轨；
2. **接触列表与身份识别**：L1 方位线 → L2 定位 → L3 分类 → L4 确认；四位数批号；六级身份；不明 ≠ 敌意；
3. **命令下达与传感器使用**：命令哈马丹号开机；中继延迟、待生效、撤销；开机暴露；
4. **政治红线**：HOLD / EVACUATE / EXPOSE；FIRE 是灾难分支。

本文把每条目标拆成可验收步骤；JSON 只存教学数据，不驱动游戏。

### 0.2 原则

- **手动触发**：每一步必须由玩家动作或玩家确认打开对应 UI 后触发；`manual_only = true`、`auto_complete = false`。
- **不以时间自动播报代替教学**：`story_l1.json` 现有的 `story.events` / `radio_lines` 时间轴仅作为作者侧排布；教学文本与提示改为玩家行动后触发（见 §4）。
- **文本不发明**：`expected_text_source` 只引用 `docs/23_Demo文本清单.md` 的 `TXT-` key；不新增设定文本、不改写对白。
- **现状可核对**：每一步标 `current_status`：`runnable`（当前 UI/动作可完成）、`partial`（已有部分，缺触发/验收/接线）、`missing`（当前缺能力）、`next_stage`（明确留到下一阶段）。
- **不伪造**：fire/weapons 未实现时，不把脚本化后果写成完整武器系统；只标 `partial` 并登记缺口。

### 0.3 状态口径

| 状态 | 含义 |
| --- | --- |
| `runnable` | 当前 V17 的 UI / 动作 / 内容已能产生该步骤的可观察结果（不需新引擎逻辑） |
| `partial` | 已有 UI、数据或动作之一，但缺少手动触发、验收或教学接线 |
| `missing` | 当前没有所需动作或反馈，不能通过现有内容完成 |
| `next_stage` | 已明确不在本阶段实现（如权威探测融合、真实武器释放） |
