## Interpretation

- **PASS** — exit code 0, probe fail count 0, all expected markers found. Marker-only boot cases require exit 0 + all markers.
- **FAIL** — nonzero exit, probe fail count > 0, missing result line, missing marker, or (boot cases) `SCRIPT ERROR` / parse error.
- **TIMEOUT** — process killed at the per-case timeout; counts as a failure for the run exit code.
- **NOT RUN** — declared blocked case (matrix `blocked: true`) or missing script/scene. Expected blocked cases do not fail the run; unexpected NOT RUN does (exit 1).
- Benign engine error lines (for example `Parent node is busy adding/removing children...`) do not fail a boot case by themselves; exit code, expected markers and fatal patterns are authoritative.
- Every case runs in a fresh Godot process with inherited `DSH_*`/`V17_*` env vars cleared; only the case-declared env is applied.
- **Baseline mode (fail-closed)** — statuses are unchanged. `known_fail` = declared baseline FAIL with matching exit/counts; `new_fail` = FAIL not declared in the baseline; `baseline_drift` = declared entry with changed exit/counts, a declared failure that now passes, or a declared entry that timed out; `baseline_unverified` = declared entry selected but NOT RUN (not executed); `baseline_unselected` = declared entry not selected by the current filters. Strict mode (default, CI) exits 0 only when complete=true (all declared entries selected + executed + expected FAIL with matching counts, no new failures/drift/timeouts/unexpected NOT RUN). `-AllowPartialBaseline` is local debugging only and always produces an INCOMPLETE label.

Overall run exit code (baseline-aware): **0** - baseline verification COMPLETE
