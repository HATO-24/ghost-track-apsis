## 2. 适用模式写在每份当前文档页首

| 模式或用途 | 产品含义 | 典型误用及迁移规则 |
| --- | --- | --- |
| 主线剧情／`full` | 现有主线流程、序章与剧情；`full` 是默认 profile | 18 的 Chronos“默认不交火／开火灾难”只属对应剧情，不写成联合战役常规交战规则；44 的开场日期不自动给战役。 |
| 联合战役／`orbital_sim` 验收 | 剧情线外、单场完整战役，有限资源、正常授权、分方情报和真实结算 | `story=false` 不能关闭战役目标；舰队名册、契约和样页都不能充当部署／AI／战役已完成证据。 |
| `sandbox`／设计样页 | 便捷试验或静态视觉审校 | 无限弹药、自动授权、假事件或合成友军轨迹不作正式战役验收；样页需醒目标数据示意。 |
| 历史版本 V15／V16／V17 某里程碑 | 追溯视觉、接口和当时测试结果 | 旧 PASS、旧“未实现”、旧小字和旧状态只在来源提交有效；新任务按真实合并树和适用场景重述。 |

## 3. 页首元数据与链接迁移

后续每份**当前入口**至少写：`适用产品／模式`、`状态（已确认／提案／实现说明／历史）`、`负责人`、`来源与取证提交`、`取代／被取代关系`、`最近核验日期`。工程测试结论另列被测 SHA、入口、命令、结果与未覆盖范围；设计稿不得只写一个“完成”。

迁移顺序：①保留原文和原路径；②新增短摘要与精确章节链接；③在旧文拟加“现行入口／当时适用版本”页眉，在新文加“历史来源”反向链接；④校验跨目录链接与两个 `40_` 的全名；⑤由负责人确认替代内容完整后，才讨论压缩正文或物理归档。`09`、`ui_v1`、`59` 的逐轮记录与原始日志首先做索引，不先删内容。

每个玩法条目保留“玩家问题→可选行动→信息来源→代价／延迟→结果→UI 反馈→失败解释”；每个文案条目保留“触发状态→位置→语义→操作后果”。删工程旁白时仍保留未知、尚未收到、过期、不可用、拒绝、请求与执行阶段。具体冲突和编辑顺序见 [盘点台账](文档盘点与冲突台账.md) 与 [重构任务卡](文档重构批次与编辑任务卡.md)。
