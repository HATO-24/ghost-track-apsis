## 3. Astra 本轮产品裁定

以下是用户委托 Astra 处理设定后的设计裁定，不能冒写为用户逐条原话。

1. **旗舰计数沿已确认决定**：11 = 8 旗舰/支援 + 3 作战。炮/导 3:0、2:1、1:2、0:3 都属于合法目标；不保证每种阵容同样容易获胜。命名、内容实例与实际部署证据另核。
2. **首个装载增量采用每舰单一主装载、舰间可不同**。这里限定本轮新增主武器弹种选择，不删除既有近防、独立对抗设备或其他合法装备。出击冻结后不可免费改型/补弹；同一主发射系统有限混装后延。库存、平台兼容、具体弹种与数值由相应工程卡收敛。
3. **同级舰通过合法舰级模板配置独立场景实例**，稳定且唯一的实例 ID、独立库存/燃料/损伤；未定新舰名可以先使用明确的场景呼号，不用缺少正典姓名阻塞四组合验证。原有具名舰身份不改，不把一个具名舰复制成三舰，也不因此扩写主线正典编制。
4. **集束与航迹仿真诱饵保留设计方向，分阶段实现**。优先逐舰装载与单体/集束比较；战术诱饵在观察者链路可用后再接。M1 打击、M2 诱饵的例子只有在平台兼容成立时适用，不能凭该示意批准导弹架通用投放。三份卡尚未提供两种完整攻击导弹规格，后续若需要双攻击导弹装载，再做有明确角色差异的窄卡，当前不凭空补齐。

## 4. 玩法判断与停止扩张的条件

值得保留的是三种不同决策：单体弹押注解算与单点效果；集束押注覆盖并承担单个命中作用下降；诱饵消耗资源以干预对手判断。多舰不同装载能让侦察、射击窗口和友军协同产生实际分工。

目前只有纸面取舍，尚未证明有趣。若集束在常见距离对重甲也总是更好、诱饵总会成功，或玩家看不出敌方反应与自己的行动有关，系统复杂度就增加了而决策没有增加。先用受控场景检验：单体/集束各有合理优势；诱饵同一次投放可被不同观察者作出不同判断；两艘同级舰各自消耗库存且改变可行战术。之后才谈继续扩弹种。

HUD 只常驻当前弹种、可用量、授权/准备状态及与本次操作相关的风险。详细机理与历史说明放展开层；技术账本不直接搬进战斗界面。这是设计要求，本批无渲染样张，不能宣称复古效果或信息负担已验收。
