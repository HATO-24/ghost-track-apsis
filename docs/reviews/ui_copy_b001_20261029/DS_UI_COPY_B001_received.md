## 3. 状态链、诊断及输入边界

业务状态/事件 → 已授权只读视图 → 文案/格式 → 现有布局；玩家动作仍经既有命令接口。原始 `reason`、消息事件、命令 ID 和日志在诊断路径保留，正常玩家文本按安全显示视图呈现。旧 `command_model.gd` 的 `QUEUED` 是等待传达，`OrderService.gd` 的 `QUEUED` 是送达后待执行；本卡禁止全局替换 `QUEUED`。发送/送达/收到/接受/执行/完成/拒绝/失败与未知/尚未收到/过期/不可用/预览继续按 61 术语分开。

**正例**：命令视图可用但无命令→“暂无命令”；通信视图不可读→“通信记录不可用”；无匹配链路→“链路状态未知”；安全正文缺失→“消息内容不可用”，原 key 留诊断。**反例**：无匹配链路显示“畅通”；空消息显示“通信失败”；缺正文在玩家面板露出 `text_key`/内部 ID；仅因 `binder.ready` 就称“实时”；把 B2 友军请求写成已接受或已执行。
