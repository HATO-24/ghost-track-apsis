# 术语表（UI 文案用）

适用范围：HUD、目标识别、命令通信、ROE、损管和舰队编制。规则继承 `docs/56_Astra_开发需求_交6Sol.md` R2 与 `docs/60_Astra_UI与文案设计规范_交Sol.md`。术语用于呈现状态；不得反向改变玩法、身份、权限或世界观。

| 术语 | UI 首选写法 | 含义与使用条件 | 不可替换为 / 禁止误读 | 来源/备注 |
|---|---|---|---|---|
| 发送 | 已发送 / 请求已发送 | 本方已发出消息或请求；只说明提交到发送路径 | 不等于送达、对方收到、接受或执行 | 56R2 §6.1 AI协同 |
| 送达 | 已送达 | 通信系统确认消息抵达指定接收端 | 不等于对方已接受命令或开始执行 | 若模型只提供 `received`，按下一条实际事件语义命名，需检查事件契约 |
| 收到 | 已收到 | 接收端收到并可见消息；用于收到回执，不宣称接受 | 不等于接受、批准、执行 | 玩家需区分交付和响应 |
| 接受 | 已接受 / 已拒绝 | 接收方对协同请求或命令作出的明确决定 | 不等于已执行/完成；不可把“请求被接受”压缩成“完成” | 友军协同反馈 |
| 执行中 | 执行中 | 行动真实启动且仍在进行 | 不等于排队、已下达或已完成 | 状态映射需来自运行服务 |
| 完成 | 已完成 | 动作达到服务定义的完成条件 | 不等于请求接受、命令送达或任务成功；战役目标成功另行表达 | 明确完成对象 |
| 失败 | 执行失败 | 已尝试但服务报告未能完成；附近给可理解原因 | 不等于拒绝（未执行）或暂时未送达 | 原始 reason code 保留于诊断 |
| 拒绝 | 已拒绝 / 未获批准 | 接收方或权限门明确拒绝；给拒绝方/原因（若可用） | 不等于通信失败、未收到或执行失败 | 授权决策 |
| 排队（`QUEUED`） | 已送达待执行 / 等待条件 | OrderService在消息到达后可将命令置为`QUEUED`；表示已送达、正在等待执行条件，不表示仍未发送 | 不要显示为发送队列中、未送达、已接受（除非另有接受回执）、已执行或已完成 | 与发送队列分开；以OrderService事件契约映射 |
| 未知 | 未知 | 当前可读视图没有足够证据判断字段值，且没有更具体的缺数状态；例如没有匹配链路记录时，不能把代码默认的`OPEN`显示为链路畅通 | 不等于友军、敌军、中立、零、正常或空字符串 | unknown identity/未匹配链路应显示未知 |
| 尚未收到 | 尚未收到 | 信息/回报按当前通信和观察边界还未到达玩家端 | 不等于目标不存在、没有发生或服务故障 | 适用于报告、友军状态、证据 |
| 过期 | 情报已过期 / 报告于{时间}前 | 数据年龄已超过该数据契约的有效期限；保留可读值时必须标旧 | 不等于当前状态仍成立；过期身份不能不加标记地当确认 | 不自行规定TTL；遵守各服务阈值 |
| 不可用 | 数据不可用 | 应用所需视图或服务暂不可读，或数据明确缺失 | 不等于未知、尚未收到、零值或“正常” | 需区分“服务不可用”与“字段未提供” |
| 预览 | 演示预览 / 模拟数据 | 明确为预览、mock、fallback或非真实会话数据 | 不称实时、当前战况、真实敌我关系；不得拿预览通过实机验收 | 若显示模拟值，标识必须邻近值/图层 |
| 实时 | 实时态势 / 当前会话 | 数据确由当前会话/授权只读视图提供，且时效有效 | 不可由 `binder.ready` 或 `SESSION LIVE` 单个旗标推导 | UI-验收需按模式和数据源确认 |
| 接触 | 接触 / 航迹 | 传感器/情报视图中玩家可见的一项目标信息 | 不等于实际物理实体总数、已知舰只或确认身份 | 情报显示集合遵循玩家视图 |
| 目标 | 目标 | 命令/战术操作的对象；显示安全名称或匿名代称 | 不显示隐藏真值名称/实体ID；接触不必然是可攻击目标 | 56R2 §4 |
| 身份评估 | 识别评估 | 基于当前证据得到的身份分类及置信/级别 | 不等于真值身份，不等于授权敌对，不等于开火许可 | IdentificationService/read view |
| 证据 | 识别证据 | 来自 transponder/IFF、ELINT、光学、手动确认等的观测或报告 | 单条应答不得被写作最终身份；保留来源、时间/时效、冲突 | 56R2 §6 Phase A |
| IFF | IFF | 敌我识别手段/应答证据之一；需按来源、时效和可信度解释 | 不等于身份真值、交战规则或开火授权；IFF应答单独不得判 hostile | 60规范样例与基线识别规则 |
| ROE | 交战规则（ROE） | DEFEND/HOLD/TIGHT/FREE 档位决定交战行为的规则 | 不等于 TRACK/SOLUTION/FIRE 授权；不得把 FREE 翻译为“自动开火” | 真实档位解释必须与服务契约一致 |
| TRACK授权 | 航迹授权 | 是否允许对目标开展对应跟踪/航迹动作的许可状态 | 不等于身份确认、武器解算或开火许可 | `combat_authorization(TRACK, ...)` |
| SOLUTION授权 | 解算授权 | 是否允许计算/使用战斗解算的许可状态 | 不等于跟踪许可、ROE或开火许可 | `combat_authorization(SOLUTION, ...)` |
| FIRE授权 | 开火授权 | 发射武器所需的独立许可状态 | 不由 ROE 或友军IFF自动授予；未授权时要贴近动作给反馈 | `combat_authorization(FIRE, ...)` |
| 友军 | 友军 | 势力/关系标记 | 不等于受玩家直接指挥，不等于其情报已共享 | 56R2 §4、§6.1 |
| 可指挥 | 可指挥 / 仅可请求协同 | 指挥权/动作权限状态。自有编队可直接命令；其他友军可能只接受协调请求 | 不从 `friend` 或列表归属推导可指挥 | 56R2要求显式指挥权限边界 |
| 协同请求 | 协同请求 | 面向其他友军舰队的支援、掩护、行动窗口或撤离协助等请求 | 未批准的请求不伪装成已下达命令；请求接受也未必已执行 | 尚未实现时只放设计样页 |
| 编制 | 舰队编制 | 将可用舰只分配到岗位/舰队的配置 | 编制合法不代表已部署、已生成实体或已出击 | 56R2指出现有Formation服务不生成实体 |
| 部署 | 部署 / 已部署 | 经实际出击/部署流程进入战场的舰只实例 | 不从编制页的 `VALID`推导部署成功 | 需有实战入口证据 |
| 舰级 | 舰级 | 档案中某类舰艇的共通信息 | 不等于该具体舰只的当前状态或配置 | catalog |
| 尚未设定 | 尚未设定 | 内容设计上尚未配置该字段 | 不等于情报未知或服务暂不可用 | 与资料缺失区分 |
| 未提供 | 当前未提供 | 当前接口/模式没有输出此字段，且原因已知 | 不得猜值或转为0；若影响玩法则拆出视图字段任务 | 文案清理不能补造接口 |
| 诊断信息 | 诊断 | source、组件名、reason code、tick、字段ID等供开发追查的信息 | 正常游玩主画面不常驻；失败的玩家意义仍须翻译显示 | 原始值可在开发模式/日志保留 |
| 任务窗口 | 行动窗口 / 目标窗口 | 任务数据明确给出的可行动时间范围 | 不得使用绘制函数里的硬编码示例值冒充正式任务参数 | 当前HUD有硬编码示例，尚需任务接口核对 |
| 协同失联 | 链路中断 / 未收到回执 | 链路无法完成投递，或请求/命令到期仍无回应；选用与事件定义一致者 | 不可笼统写“被拒绝”或“执行失败” | 通信/AI任务卡需定义超时边界 |

## 对候选文案的审校顺序

1. 先判定语义：命令阶段、权限、身份、数据来源与时效。
2. 再判定数据状态：未知、尚未收到、过期、服务不可用、字段未提供、预览。
3. 最后压缩字数。若字数优化导致阶段/来源/授权变化，保留准确表述并移到详情区。
4. 没有已实现接口时写“设计样页/接口待定”，不在文案表中替服务承诺参数、默认队形、舰数或 AI 行为。
