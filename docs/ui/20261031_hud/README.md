## 依赖与本轮可做的事

`A1 已合入 → UI-01（主屏/ROE 有限映射） → UI-02（真实字体度量、字号与组件） → UI-03（四区、选择/焦点/命令反馈，含 B001） → UI-04a/b（分别随 B1 部署、B2 协同接口）`。UI-03 仍需 A1/所触业务 view 稳定；UI-04 不能由设计样页宣称已实现联合战役。

第一有界切片只处理正式 `orbital_sim` HUD 中 **确定无数据权威的装饰计时、固定链路畅通、固定任务窗口和开发旁白**，并在真实 `build_profile.id/label`、`session.now_s()`、`combat_service` 可用性支持的条件下保留模式、时标和 ROE 的如实显示。先采无扫描/辉光的可读基线，再保持深色终端、磷光绿重点、细线框、轨道几何和琥珀/红的风险层级。该切片只允许现有 `v1_hud.gd` 的局部显示/初始化调用；若唯一持有人未确定，先停在 CSV 映射，不碰生产代码。实际字体/测量、布局与焦点重构留 UI-02/03。

**缺字段停行**：`_roe_locked` 在无 story 的 `orbital_sim` 由默认 `prelude` 推成锁定，且可被环境变量覆写；这不是经授权 view 给出的锁定原因。ROE 锁定说明与 `_roe_action` 反馈需先有真实可编辑/拒绝 reason 合同。顶栏链路没有可信状态/延迟就移除装饰值，不填“畅通/0 秒”；任务窗口、倍率、授权状态也不从装饰文本推断。`binder.ready` 只代表 boot 错误数组为空，不证明每个 view 实时可读。`_contacts` 为空时 HUD 还会合成 `demo=true` 占位接触；这也不能单独证明数据来自预览。低质量/未知观测绝不由 UI 自动禁射；火控仍按独立授权规则裁决。

CSV 区分：**文案候选/既有原文**、**真实消费字段及其来源/权限**、**仍待正式入口实机证明的可读与交互证据**。行中“可做”仅是可派实现范围，不是已获产品验收的文字或运行 PASS。
