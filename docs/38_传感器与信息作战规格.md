> 上游：`docs/37_真实空间与信息作战架构.md`（总架构、单一权威、分层、可回退）、`docs/11_传感器规则.md`（V1.5 数值与等级）、`docs/05_技术手册.md` §3/§5/§6（S-01…S-07、E-01…E-03、C-01…C-05）、`docs/14_通信与中继.md`、`docs/19_通信格式与批号.md`。

## 0　文档定位与不变量

### 0.1　本规格解决什么问题

R5 之前，传感器/信息作战存在三套事实来源：

1. `game_v15/scripts/sensor_model.gd`：V15 HUD 的接触等级、融合、威胁、暴露判定（**当前 V17 唯一权威**）；
2. `game_v17/framework/sim/{sensor_types,radar,tws,optical}.gd`：V2 模型/演示数据（当前是 advisory）；
3. `sensor_explorer/sim/*` 与 `sensor_explorer/scripts/sensor_model.gd`：独立验证台（非游戏权威）。

R5 必须收敛为**一套权威**：几何/姿态 → 传感器观测 → 航迹证据/等级/身份 → EW/通信/指挥 → UI。否则会出现「HUD 显示 L2、逻辑按 L3 结算」「V15 融合与 V2 TWS 各判一套」「ELINT 信号被 UI 当成接触」等双套判定。

### 0.2　不可破坏的约束（来自 docs/37）

- **单一权威**：同一时刻只有一个模块能写「航迹等级/身份/位置证据/暴露/干扰效果」。权威切换由显式状态机控制，不允许运行时隐式双写。
- **分层**：`core`（实体/状态/权威）→ `sim`（物理/传感器/EW 模型）→ `ui`（只读 view-model）。`ui` 不反向写 sim/core。
- **单一写入者**：UI/plot 不得调用 `SensorModel.detect*/update_track/age_track` 或修改 `state.tracks` 的等级/身份字段；它们只能读取权威归一化后的 `tracks/contacts`。
- **可回退**：任何阶段都能用环境变量/开关回到 `legacy_v15`；验证台和旧 demo 不删除，只降级为「只读/参考」。
- **V1 HUD 视觉**：新增数据只通过 V1 密度的线框/小字/独立窗表达，不引入 V2 大留白页面；HUD 主屏只留摘要。
- **先 probe 后接入**：任何模型进入 V17 前必须有 headless probe 与确定性断言；没有 probe 的模型只能留在验证台。

### 0.3　权威切换的三种运行模式（R5 的目标状态机）

| 模式 | 权威 | 用途 | 写入规则 |
| --- | --- | --- | --- |
| `legacy_v15` | `game_v15/scripts/sensor_model.gd` + V15 `state` 融合 | 当前 V17 默认；旧 demo/截图/回归 | 只有 V15 state 写 `state.tracks`；V2 只读 advisory |
| `shadow` | V2 `SensorAuthority` 计算完整结果；V15 仍写显示 | R5 迁移中对比、回归；不改变玩家可见结果 | 只允许 V2 写自己的 shadow 快照；**任何人不得把 V2 结果写回 V15 state**；对比器只读 |
| `v2_authoritative` | V2 `SensorAuthority` + `world` | R5 完成目标 | **只有 V2 authority 写世界/航迹/事件**；V15 state 只做 adapter（把 V2 view-model 归一成 HUD 字段） |

> 切换只允许由 `state.set_sensor_authority(mode)` / 启动环境变量触发。禁止「某个传感器单独切」「HUD 局部切」。  
> 正式默认值在 R5 收口时由验收决定；R5 开发期默认 `legacy_v15`。

## 1　术语、等级与身份

### 1.1　术语

| 术语 | 含义 |
| --- | --- |
| 实体 / Entity | 有位置/速度/姿态/质量/RCS/热特征/挂载的物理对象（舰、站、储罐、穿梭机、诱饵、残骸） |
| 观测 / Observation | 单传感器单次测量的原始结果（可能只有方位、可能失败） |
| 航迹 / Track | 融合后的目标状态（批号、位置/协方差、等级证据、身份证据、来源、时效） |
| 证据 / Evidence | 支持某个等级/身份的带时间戳来源（`bearing`、`range`、`classification`、`identity`、`signature`…） |
| 接触 / Contact | UI 显示的航迹视图（对 HUD 而言是 `state.tracks` 的一行） |
| 发射源 / Emitter | 任何主动辐射对象（雷达、IFF 询问、通信发射、激光、干扰机、诱饵） |
| 信号 / Signal | ELINT/COMINT 的被动截获结果；**不是接触**（无位置、无距离时尤其） |
| 效果 / Effect | EW/通信/损管对传感器或链路的作用，进入同一事件总线 |

### 1.2　接触等级（沿用 docs/11 §1.2；R5 不新增等级）

| 等级 | 定义 | 可产生它的权威证据（R5） |
| --- | --- | --- |
| L0 | 无接触 | — |
| L1 | 仅方位、无距离解；IR 附远/中/近三档 | IR 观测、光学未锁定观测、单站 ELINT 不能单独产生接触（见 §7） |
| L2 | 有位置证据（定位） | 雷达测距、双站/多站方位交叉（光学/IR/ELINT 联合） |
| L3 | 分类（舰级/船厂/使用方/角色） | 光学凝视完成（VIS）、ELINT 指纹匹配、数据库比对 |
| L4 | 具体身份（舰名/舷号/阵营/呼号） | IFF 应答正确 + 注册库/编队链路、信号指纹 + 数据库强匹配 |

- **等级与身份分离**：身份 `identity ∈ {unknown, assumed_friend, friend, neutral, suspect, hostile}` 是独立字段；L3 只到「舰级」，不自动给舰名；L4 只在权威身份证据成立时设置。
- **不明 ≠ 敌意**（docs/05 §S-06、docs/07）：无应答/无信号/超距只导致 `unknown` 或 `pending`，不得输出 `hostile`；敌意只能由指挥/ROE/事件（如开火、明确宣告）或可信身份源写入。

### 1.3　「唯一权威」的准确含义

- 不是「只有一个文件」，而是「同一事实只有一个写入者」：
  - 几何/姿态：`core` 实体/轨道权威（R3/R6）；
  - 观测：`sim/sensor_authority`（唯一传感器管理器）产生；
  - 航迹/等级/身份：`core` 航迹表（唯一写者，使用观测/证据）；
  - 暴露/干扰/通信效果：同一事件/状态总线（见 §6–§8）；
  - 显示：`ui` 只读归一化视图。
- `sensor_model.gd`、`sensor_explorer`、`sensor_explorer` 的模型库是**参考实现/验证台**；R5 后 V15 路径只在 `legacy_v15` 模式保留作为回退，不得与 V2 同时驱动显示。

## 2　单一权威数据流

### 2.1　数据流总图（文本版）

```
实体/姿态/几何/环境（core: entity, orbit, attitude, sun/moon, station, damage）
        │
        ├─ 传感器挂载状态（mounts, on/off, EMCON, mast, damage, pointing）
        │
        ▼
V2 SensorAuthority（唯一传感器管理器）
  ├─ 传感器模型库（radar / tws / optical / ir / iff / elint / comms）
  ├─ 环境帧（LOS、sun illum、earth albedo、jamming、comms jamming、weather）
  └─ 产生 SensorObservation / EmitterSignal / CommsObservation / EWEffect
        │  publish（同一事件总线）
        ▼
core ObservationBus / EventBus（唯一状态入口）
        │
        ▼
core TrackTable / EvidenceStore（唯一航迹写者）
  ├─ level_evidence[] / identity_evidence[] / covariance / sources / age / stale
  ├─ EW/通信效果并入事件与状态（不单独维护第二套威胁）
  └─ 产生 normalized_contacts（UI view-model）
        │
        ├─ state adapter（V17：V15 字段映射；只读）
        ▼
V1 HUD / plot / 独立窗口（只读）
```

### 2.2　每一步的职责与频率

| 步骤 | 责任方 | 输入 | 输出 | 频率 |
| --- | --- | --- | --- | --- |
| 几何/姿态 | `core` | 轨道、姿态、损伤、站体 | `EntityStateSnapshot` | 物理 tick（≥10 Hz 或固定 dt） |
| 环境 | `core`/`sim` | 太阳/月球/地球、遮挡、干扰机状态 | `EnvironmentFrame` | 每物理 tick（缓存 1 s 可视） |
| 传感器 | `sim/sensor_authority` | 实体 + 环境 + 挂载 | 观测/信号/通信/EW 事件 | 每传感器 `refresh_s`；融合 1 Hz |
| 观测总线 | `core` | 观测/信号 | 事件入队、去重、时间戳 | 每次观测 |
| 航迹融合 | `core` TrackTable | 观测/证据 | 航迹状态、等级、协方差 | 1 Hz（`FUSION_PERIOD_S=1.0`） |
| 效果合并 | `core` EventBus | EW/通信事件 | 环境修正、命令延迟、假批号标记 | 事件到达即合并，1 Hz 结算 |
| UI 归一化 | `state` adapter | 航迹/flow/信号 | `state.tracks`/`fw_*` | 每帧只读快照 |
| UI 绘制 | `hud/plot` | 归一化视图 | 像素 | 每帧 |

### 2.3　单一写入规则（可 CI/代码审查的硬约束）

1. `sim/sensor_authority.gd` 是**唯一**允许调用传感器模型库并产生观测的地方；`hud.gd`/`plot.gd`/`state.gd` 不得直接 `preload`/调用 `sensor_model.detect*`（`legacy_v15` 适配器除外）。
2. `core/world.gd`/`core/track_table.gd` 是**唯一**允许写航迹等级/身份/协方差/威胁的地方；`state` 只做归一化映射（`track.weapon_release` 等展示字段除外）。
3. UI 只能通过公开 view-model 字段与动作 API 读/写（动作由 world 执行），不得「为了显示」改等级。
4. 事件/效果必须进同一 `EventBus`，不得有独立 EW/通信脚本直接改 `state.tracks`。
5. 两套数据同时存在时（迁移期），必须由 `authority` 状态决定「谁是权威」，且**shadow 模式禁止回写**；对比只读。
6. 任何「新传感器/新 EW 效果」必须有 probe，且 probe 断言只写一个状态。

### 2.4　V17 切换点（摘要；详见 plan 文档）

| 切换点 | 当前（R4） | R5 目标 |
| --- | --- | --- |
| `state.sensor_authority` | 恒 `legacy_v15` | `legacy_v15 / shadow / v2_authoritative` 状态机 |
| `state.fw_sync()` / `framework.sync()` | 只同步 flow/damage/replay/contacts | 增加 `sensors` 归一化快照；authoritative 模式下由 V2 写显示接触 |
| `scripts/tws_bridge.gd` | V15 只读驱动 V2 TWS，plot 叠加 | 改为「authority 通道 viewer」；`legacy` 时仅演示叠加 |
| `scripts/state.gd::_fusion_tick` | V15 `sensor_model` 融合 | authoritative 模式下停用（或只读回退）；由 core TrackTable 产出 `state.tracks` |
| `hud.gd`/`plot.gd` | 读 `state.tracks`、rack、TWS bridge | 读同一 state 字段（adapter 归一化），不新增判定；TWS/光学/ELINT/EW 细节进独立窗 |
| 动作/传感器开关 | `set_sensor`/EMCON 改 V15 | authoritative 模式下写 core authority（通过 world API），V15 仅是视图 |

## 3　公共数据结构与事件总线

> 以下为**跨语言/存档/测试的稳定 schema**；JSON 示例省略注释，实际实现用 GDScript `Dictionary` + `to_dict()`。所有字段必须有版本号。

### 3.1　`EntityStateSnapshot`（几何/姿态/损伤）

```jsonc
{
  "schema": "entity_state.v1",
  "t": 1234.5,                       // 仿真秒（权威时钟）
  "entities": [{
    "id": "harmattan",
    "kind": "ship|station|tank|wreck|shuttle|decoy",
    "pos_km_l1": [x, y, z],          // 显示/局部板
    "vel_kmps_l1": [vx, vy, vz],
    "pos_km_eci": [x, y, z],         // 物理积分系（R6）
    "vel_kmps_eci": [vx, vy, vz],
    "attitude_quat": [x, y, z, w],   // 舰体→L1/ECI（按 config）
    "angular_rate_dps": [p, q, r],
    "rcs_m2": 10.0,
    "thermal": {"temp_k": 300.0, "area_m2": 1000.0, "plume": 0.0},
    "damage": {"sensors": 1.0, "comms": 1.0, "propulsion": 1.0},
    "mounts": [...],                 // 见 SensorMount
    "emcon": false,
    "mast_deployed": true
  }]
}
```

单位约定：距离 km、速度 km/s、姿态四元数（归一化）、角速度 deg/s、RCS m²、温度 K、面积 m²。显示层不得私自换单位/插值权威数值。

### 3.2　`SensorMount`（挂载/配置/运行时）

```jsonc
{
  "mount_id": "harmattan/YW-R9",
  "ship_id": "harmattan",
  "model": "YW-R9",
  "kind": "search_radar|tws_radar|optical|ir|iff|elint|radio|lasercom",
  "subtype": "lidar|datalink|...",
  "enabled": true,                   // 玩家/EMCON 开关
  "destroyed": false,
  "mast_dependent": true,
  "pointing": {"mode": "gimbal|fixed|body", "boresight": [az, el], "slew_rate_dps": 2.0},
  "params": {
    "range_km": 30000.0,
    "refresh_s": 6.0,
    "aperture_m": 1.2, "focal_m": 4.8, "fov_deg": 0.244, "ifov_urad": 1.04,
    "stare_s": 40.0, "stare_ref_km": 8000.0,
    "jamming_resist": 0.2, "lpi": false,
    "min_snr_db": 8.0, "sigma_bearing_deg": 0.15
  }
}
```

运行时状态（不写进静态配置）：`on_time_s`、`channel_count`、`last_scan_t`、`temperature`、`fault`。

### 3.3　`EnvironmentFrame`（判定环境）

```jsonc
{
  "schema": "environment.v1", "t": 1234.5,
  "sun": {"dir": [x,y,z], "illum": 1.0},
  "earth": {"pos_km": [...], "radius_km": 6378.137, "albedo": 0.30},
  "moon": {"pos_km": [...], "radius_km": 1737.4, "albedo": 0.12},
  "shadow": false,                      // 目标/本舰是否在地球/月球阴影
  "weather": {"optical_transmittance": 1.0},
  "jamming": [{"source_id":"...", "kind":"noise|deception", "freq_band":"...", "power_db": 0.8,
               "affected_kinds":["radar"], "falloff":"none|linear"}],
  "comms_jamming": [{"source_id":"...", "band":"radio", "severity":0.7, "against":"..."}],
  "emcon": {"harmattan": false},
  "comm_links": [{"from":"harmattan","to":"apsis","mode":"lasercom","los":true,"latency_s":0.5}]
}
```

环境是**只读输入**；EW 改环境也必须经 EventBus 的 effect 结算，不允许传感器模型直接读某个 EW 全局单例。

### 3.4　`SensorObservation`（单传感器观测）

```jsonc
{
  "schema": "sensor_observation.v1",
  "id": "obs-000123",
  "t": 1234.5,
  "observer_id": "harmattan",
  "mount_id": "harmattan/MS-OT2",
  "target_id": "2001",                 // 真实实体（权威内部使用；UI 只拿 track id）
  "kind": "ir|radar|optical|iff|elint|comms",
  "sensor_model": "MS-OT2",
  "detected": true,
  "pd": 0.86,
  "level_support": 1,                  // 本观测能支撑的最高等级（0..4）
  "produces_contact": true,
  "bearing_deg": 40.99,
  "bearing_sigma_deg": 0.05,
  "range_km": -1.0,                    // -1 = 无距离解
  "range_sigma_km": -1.0,
  "range_band": "near|mid|far|",       // IR 三档
  "quality": 0.86,
  "snr_db": 12.3,
  "classification": {},                // L3 证据（VIS 锁定后）
  "identity": {},                      // L4 证据（IFF/链路/数据库）
  "iff_status": "",                    // no_reply|wrong_code|faulty|friend|captured...
  "signal": {},                        // ELINT 信号（见 3.6）
  "notes": [], "reason": "",
  "expose_self": {},                   // 本观测导致的暴露（主动传感器）
  "source": "sim/sensor_authority"
}
```

### 3.5　`TrackEvidence` / 航迹状态

```jsonc
{
  "track_id": "2001", "batch": 2001,
  "level": 2, "level_evidence": [
    {"level":1,"source":"CH-IR2","t":1200.0,"kind":"bearing"},
    {"level":2,"source":"YW-R9","t":1230.0,"kind":"range"}
  ],
  "level_max_seen": 3, "last_level_t": 1230.0,
  "identity": "unknown", "identity_evidence": [],
  "iff_status": "no_reply",
  "classification": {}, "signal": {},
  "bearing_deg": 41.0, "range_km": 318.0, "range_band": "",
  "covariance": {"pos_sigma_km": 2.1, "semi_major_km": 3.0, "semi_minor_km": 1.2, "age_s": 1.0},
  "sources": ["MS-OT2","YW-R9"], "stale": false, "age_s": 1.0,
  "phantom": false, "spoof_flags": [], "threat": "none|low|...",
  "authority": "v2_sensor"
}
```

规则：
- `level` 只能由 `level_evidence` 在 1 Hz 融合中计算（`level_from_evidence`），不是 UI 推断；
- 等级会随时间/失去刷新逐级降级（`LEVEL_VALID_S`）；降级同样由权威写；
- 位置/协方差由证据决定；仅方位证据的径向协方差要显著大（「不确定性可画出来」）；
- `threat` 不是传感器等级：由指挥/ROE/身份/行为评估写入，必须有独立证据（R5 可不实现自动威胁，只保留字段与「不明不自动敌意」）。

### 3.6　`EmitterSignal`（ELINT / COMINT）

```jsonc
{
  "schema": "emitter_signal.v1",
  "id": "sig-0007", "t": 1234.5,
  "observer_id": "harmattan", "mount_id": "harmattan/ELINT",
  "source_id": "2001",                   // 对已知实体的关联；未知则为 ""
  "bearing_deg": 40.8, "bearing_sigma_deg": 1.0,
  "range_km": -1.0,                      // ELINT 本身无距离
  "freq_mhz": 9500.0, "band": "X",
  "prf_hz": 1200.0, "pulse_width_us": 1.2, "scan_period_s": 6.0,
  "power_db": 0.72, "snr_db": 15.0,
  "signature": "YW-R9", "matched": true, "confidence": 0.8,
  "class_hint": "R-9 搜索雷达", "level_support": 3,
  "produces_contact": false,             // 铁律：单站 ELINT 不产生接触
  "comms_content": null,                 // COMINT 时填写 text/links/encryption
  "spoof_flags": [], "notes": []
}
```

### 3.7　`EWEffect`（电子战/通信效果）

```jsonc
{
  "schema": "ew_effect.v1",
  "id": "ew-0042", "t_start": 1234.5, "t_end": 1254.5,
  "source_id": "2001", "source_mount": "ELINT-JAM",
  "effect": "noise_jam|deception|chaff|false_target|comms_jam|comms_spoof|emcon|lwr|laser_dazzle",
  "target_id": "harmattan", "target_kinds": ["radar","elint"],
  "severity": 0.7,                       // 0..1
  "params": {"band":"X", "freq_mhz":9500.0, "latency_s_add": 12.0},
  "evidence": {"source":"signal", "confidence":0.7},
  "authority": "v2_sensor",
```

## 4　统一检测与融合管线

### 4.1　单次探测的统一步骤（所有传感器共用）

1. **可用性**：挂载 `enabled && !destroyed`、电源/热控/桅杆/EMCON、通道容量、冷却；
2. **几何**：`r = target.pos - observer.pos`，距离、方位、俯仰、相对速度、相对角速度；
3. **视线**：`los_ok`（地球/月球/站体遮挡；光学/激光还需光轴/视场）；
4. **环境**：光照/阴影/地球反照（光学）、热对比（IR）、干扰（雷达/通信）、天气；
5. **检测概率**：按模型 `Pd` 掷骰（默认确定性 seed；probe 可固定）；
6. **测量**：产生测量 + σ（方位/距离/波段/分类/身份证据），或失败原因；
7. **发布**：`SensorObservation` → EventBus → TrackTable 融合；
8. **融合/老化**：1 Hz 更新等级证据/协方差/陈旧；写回 `TrackState`；
9. **发布等级/身份事件**：只由 TrackTable 发布 `track.level/identity`。

### 4.2　统一公式

- 探测概率（docs/11 §7.3）：
  `SNR_dB = −10 n log10(R/R_ref)`, `n=2` 单程（IR/光学/ELINT），`n=4` 双程（雷达/激光），`Pd=1/(1+e^(−0.5·SNR_dB))`。
- 雷达：`R_eff = range_km · (σ_rcs/10m²)^0.25 · (1 − jamming(1−0.30)(1−jamming_resist))`。
- IR：`contrast=(T/300K)^4·(A/1000m²)·shadow_factor`，`R_eff=range_km·sqrt(contrast)`。
- 光学：`R_eff=range_km·sqrt(illum)`；详见 §5。
- 方位/距离测量误差：按型号 σ；航迹协方差 `σ_cross = R·σ_b + 0.5a·age²`，`σ_radial = σ_r + 0.5a·age²`；`a=0.00098 km/s²`。
- 等级有效期：L4=30s，L3=90s，L2=210s（docs/11 `LEVEL_VALID_S`），失去刷新逐级降级，不删除航迹。

### 4.3　融合的唯一规则

- 每个融合周期，从所有“未来自同一来源重复”的观测/证据中选出**每级最高可信证据**；
- 只有 `TrackTable` 能决定 `level = max(level_support of valid evidence)`，并按有效期降级；
- `classification` 只接受 L3 证据（光学锁定/ELINT 指纹/数据库），`identity` 只接受 L4 证据（IFF 正确+注册库、编队链路、强指纹）；
- 同一目标的多来源证据合并为 `sources[]`；`phantom/spoof_flags` 不允许静默丢弃，应在 UI/审计中显示；
- 融合结果是唯一显示事实：**UI 不重新计算、不覆盖**。

### 4.4　身份判定（强制收敛）

- `identity` 是证据结果，不是侧别（`side`）的 UI 推断；
- IFF 正确应答：`friend` 仅在注册库/编队链路确认后写 L4；缴获码/复制码置信度 ≤0.5 并加 `spoof_flags`；
- 无应答/故障/超距：`unknown` 或 `pending`，不写 `hostile`；
- `hostile` 只来自：明确敌意行为事件（开火/锁定/闯入禁区）、可靠情报/指挥授权、或已验证的敌方注册身份；且必须有 `identity_evidence` 记录；
- 「不明不自动判敌」在 HUD 显示为 `不明`，不是「敌」；图例与文案沿用 docs/11/09。

## 5　光学 / IR 功能规格（VIS / IR）

> 目标：把光学从「一个凝视进度环」提升为可解释的真实功能：口径/焦距/视场/像素、光照/遮挡/相对角速度、凝视/分类限制；输出等级与通道窗 API。当前 `sim/optical.gd` 已有凝视/光照/遮挡/失锁状态机，但**没有物理光学参数、FOV/IFOV、相对角速度、真实分类判据**；R5 在其上扩展，不替换其状态机语义。

### 5.1　型号配置（R5 基线，全部字段必须进数据表）

### 5.2　光学几何与分辨率

- 角分辨率（探测器）：`IFOV = pixel_pitch_um×1e-6 / focal_m`（rad）；受衍射限制：`IFOV_eff = max(IFOV, 1.22·λ/D)`。
- 目标角尺寸：`θ_t = size_m / R_m`；像素覆盖：`N_px = θ_t / IFOV_eff`。
- 可视距离（分类）：`R_classify_max = size_m / (classification_px·IFOV_eff)`；同时受 `range_km`/光照限制。
- 目标在视场内：`|LOS - boresight| ≤ FOV/2`（万向架指向、姿态稳定）；偏离则 `out_of_fov`。
- 视场扫描：万向架转速 `slew_rate_dps`；大范围搜索需按扫描模式逐步指向，不能「瞬间看到全空间」。IR 阵列可固定宽视场（FOV 0.733°，仍非全向）。

### 5.3　光照、遮挡、背景

- 可见光检测条件：`sun_illum >= illum_min` 且目标未被地球/月球遮挡，且相机侧无遮挡；`illum = sun_vis × (1 - shadow) × optics_transmittance`；地球反照可作为弱补光（`earth_albedo` 因子，默认 0.03，仅提升近地目标，不改变等级上限）。
- 阴影（地球/月球）→ `lost/shadow`；IR 不受可见光阴影影响，但受背景/热对比影响（`IR` 仍可跟踪阴影内目标，符合 05 S-01）。
- 太阳直射/眩光：若视轴接近太阳（角距 < `sun_avoid_deg` 5°），光学进入 `dazzled` 状态（Pd 降为 0.1，持续到离开）；激光致盲作为 EW 效果（§8）。
- 光学证据可用于取证：锁定帧/分类结果写入证据日志，供 REPORT 使用（不改变等级规则）。

### 5.4　凝视、相对角速度、运动模糊

- 凝视需求（沿用 docs/11）：  
  `stare_req = clamp(stare_s_ref × (R/stare_ref_km)^2 / quality_factor, 4 s, 240 s)`；  
  `quality_factor` 默认 1.0，受光照/对比/大气修正；IR：`stare_req = 4 s`（锁定不等于分类）。
- 相对角速度：`ω_rel = |r × v_rel| / |r|²`（rad/s），加上本舰姿态角速度在视轴上的投影（固定安装时）。  
  `smear_px = ω_rel × exposure_s / IFOV_eff`；若 `smear_px > 0.5` → 图像模糊，凝视进度按 `1/(1+smear_px)` 缩放/重置（取模型设定，建议 >1 px 时重置）。
- 平台中断：自舰机动 `> reset_maneuver_g` 或姿态角速度 `> 0.5°/s` → VIS 凝视重置（与当前 `sim/optical.gd` 一致）；IR 阈值放宽到 0.05 g / 1.0°/s（IR 更耐机动，【定义】）。
- 目标相对运动：目标相对角速度超过 `track_rate_dps` 时，万向架需连续跟踪；超过能力则 `lost` 并可重捕。
- 状态机（保持当前 V2 语义）：
  `idle → acquiring → staring → locked`；条件不满足 → `lost`（保留 `lost_hold_s` 进度后清零）；重新满足 → `acquiring`。新增失败原因：`shadow|out_of_fov|occluded|out_of_range|dazzled|smear|track_rate`。

### 5.5　VIS/IR 输出等级与限制（铁律）

| 通道 | 输出 | 等级上限 | 禁止 |
| --- | --- | --- | --- |
| VIS | 方位（σ 0.05–0.06°）、锁定后 `classification`（舰级/船厂/使用方/角色） | L3（锁定后）；锁定前仅 L1 | 不给舰名/舷号/阵营身份；不给距离解 |
| IR | 方位线（σ 1.2°）、远/中/近三档 `range_band`、热对比/热分类（可选） | L1（IR 不升 L3；**IR 锁定 ≠ 分类**） | 不分类舰级、不给身份/距离、不自动判敌 |
| 激光测距 LR-4（optical 子型） | 精确距离（σ 0.2 km） | L2（不升 L3/L4） | 不代替分类/IFF；只有目标 LWR 收到（ELINT 截获距离 0） |

- VIS 分类完成必须同时满足：`stare >= stare_req`、`N_px >= classification_px`、`illum` 达标、无遮挡/眩光、`smear_px <= 0.5`；输出 `classification{ship_class,role,faction,confidence}`，**不输出 `identity`**。
- IR 锁定只表示“热源稳定跟踪”，不能升级到 L3；若目标同时被 ELINT/光学/数据库支持，才能由融合升 L3/L4。
- 光学/IR 均为被动：`expose_self={}`（不暴露）；激光测距是微弱主动（仅 LWR），不产生 ELINT 截获。

### 5.6　通道窗 API（同步到 HUD 独立窗）

权威提供（只读快照 + 控制方法；HUD/独立窗只调这些）：

```gdscript
# 数据（只读）
sensor_authority.channels(kind := "") -> Array[ChannelView]
sensor_authority.channel(kind, target_id) -> ChannelView
sensor_authority.optical_summary() -> Dictionary
# 控制（玩家动作，仍由 authority 校验）
sensor_authority.start_channel(kind: "optical"|"ir"|"lidar", target_id, opts := {}) -> Dictionary
sensor_authority.stop_channel(kind, target_id := "") -> void
sensor_authority.set_mount_enabled(mount_id, on) -> Dictionary
```

`ChannelView` 至少包含：
`kind/status/progress/stare_s/required_s/refresh_s/samples/slant_range_km/measured_range_km/range_band/bearing_deg/bearing_sigma_deg/illum/contrast/effective_range_km/snr_db/ifov_urad/fov_deg/pointing_deg/boresight_deg/smear_px/level_support/classification/reason/locked_t/lost_at/predicted_next_t`。
HUD 通道窗仅显示该结构；不自行计算 `required_s`/状态机（当前 `ui/channel_window.gd` 读 `state.fw_sensor`/snapshot 的迁移见 plan）。

### 5.7　光学验收数值（probe 必测）

- FOV/IFOV 与 `detector_px/pixel_pitch/focal` 一致（误差 <1e-6 rad）；
- `N_px(50 m @ 15,000 km)` = 3.2 px（MS-OT2）→ 允许分类；`@ 30,000 km` = 1.6 px → 不可分类（只能 L1）；
- 阴影 → `lost/shadow`；IR 在阴影内仍锁定（IR 通道独立）；
- `smear_px>0.5` → 凝视不涨/重置；自舰 0.03 g 机动 → VIS 重置；
- IR 锁定 4 s 且 `level_support=1`，**不得**升 L3；VIS 锁定后 `level_support=3`，且 `identity` 仍为 `unknown/pending`；
- 同一目标 VIS+IR 通道可同时存在，互不覆盖；停止一通道不影响另一通道；
- `start_channel` 无传感器/超容量/目标不存在 → `{ok:false,reason}`，不改状态。

## 6　IFF 规格（写实收敛）

> 目标：把 IFF 从「按钮给友军」变成有模式/编码/应答/欺骗/无应答的身份证据设备；保持「不明不自动判敌」。

### 6.1　设备与信号

- 型号：MK-12 询问应答机（V15 型号；R5 可沿用虚构名，参数按真实 IFF 逻辑设计）。
- 频段/波形：UHF 询问/应答（1030/1090 MHz 类），脉冲编码；模式：
  - Mode 1：任务/任务组码（2 位八进制，军事任务）；
  - Mode 2：单位码（4 位八进制，部队/单位）；
  - Mode 3/A：识别码（4 位八进制，12-bit，民航/军用）；
  - Mode C：高度码（与 3/A 联动，气压高度量化）；
  - Mode S：24-bit 地址 + 选择性询问（本作可选）；
  - Mode 5：加密询问/应答（友军密钥/时间同步；本关可用 `crypto_epoch`）。
- 距离：2,000 km（docs/05 S-06）；询问周期 2.0 s；询问即暴露：ELINT 截获距离 4,000 km、12 s 可定位（docs/11 §6.1 权重 0.6）。
- 应答内容：模式、代码、单位/任务、高度、密钥有效性、机型/注册信息（可选）；**应答正确不等于友军**（缴获码/复制码风险）。

### 6.2　询问/应答流程（权威内状态机）

```
idle → interrogating(target, modes, code?) → waiting_reply(≤ timeout 2s)
     → resolved(reply_ok) | no_reply | faulty | wrong_code | captured | out_of_range
     → cooldown(2s) → idle
```

- 条件：目标在 2,000 km、视线无遮挡、目标应答机开机（`transponder` 状态 `ok|faulty|off|captured`）、加密模式需密钥匹配。
- `no_reply`：可能是敌军、故障、静默友军、超距、遮挡 → **identity=unknown**，`warning="不明 ≠ 敌意"`；
- `wrong_code`：代码不匹配 → `identity=suspect?` **不得直接 hostile**，只标记 `iff_status=wrong_code` 与 `confidence`；
- `faulty_transponder`：友军应答机故障（docs/07 谷神-2）→ unknown + 技术告警，不判敌；
- `captured`/复制码：应答可接受但 `confidence≤0.5` + `spoof_flags=["captured_code"]`，不得单独升 L4；
- `crypto mismatch/expired`：Mode 5 失败 → unknown；不泄露是否为敌；
- 身份写 L4 仅在正确应答 **且** 注册库/编队链路/舰名匹配确认后；否则只给“友军可能/不明”。

### 6.3　欺骗、干扰与反制

- 缴获码/复制应答：可伪造 `friend`，但置信度低 + 警告；需第二来源（光学/ELINT/编队链路）交叉验证。
- IFF 干扰/压制：噪声/欺骗导致 timeout 或错误码；不得自动降为 hostile。
- 反制：加密模式（Mode 5）、时间/密钥轮换、多模式组合、编队链路交叉核验。
- IFF 询问是主动发射，进入 ELINT/暴露总线；对敌 ELINT 可见（4,000 km / 12 s 定位）。

### 6.4　API 与输出

```gdscript
sensor_authority.interrogate_iff(target_id, modes := ["3/A","C"], opts := {}) -> Dictionary
# -> {ok, status, modes, code, reply, confidence, identity_evidence, expose_self, cooldown_s, reason}
sensor_authority.iff_state(target_id) -> Dictionary
```

输出只进 `identity_evidence`（L4）与 `iff_status`/告警；**不产生位置**；不得写 `hostile`。
probe 必测：friend/no_reply/faulty/wrong_code/captured/out_of_range/timeout；询问失败不改等级；缴获码置信度 ≤0.5；IFF 不产生接触/距离；询问暴露进总线。

## 7　ELINT / COMINT 规格

> 目标：被动截获与测向写实；单站只给信号/方位，不产生接触；多站交叉定位作为 L2 候选；与通信侦察（COMINT）区分；不自动判敌。

### 7.1　ELINT 接收机与截获

- 设备：通用 ELINT 接收阵列（被动、全向/多基线测向）；R5 可选 2 站/3 站联测。
- 参数：频率范围 0.5–18 GHz（本作 S/X/Ku 等）、灵敏度 `S_min dBm`、测向 σ（默认 1.0°，docs/11）、瞬时带宽、扫描周期；`range_km=60,000`（对强辐射源，docs/11 §3.6）。
- 截获链路预算（自由空间）：
  `P_r(dBm) = P_t(dBm)+G_t(dBi)+G_r(dBi)+20log10(λ/(4πR_m))−L`；
  `SNR = P_r − N_floor`；`SNR≥threshold` 才 detected。
- 截获条件：发射源在频段/波束/扫描覆盖内、非静默、无遮挡、功率足够；扫描接收机需等待扫描驻留（`intercept_delay_s`）。
- 测向：幅度/相位干涉仪；`bearing_deg ± σ`；单站**只有方位**。
- 指纹：频率/PRF/PW/扫描/调制 → `signature` 与 `matched`；未知特征 → `signature=""`、confidence 低；指纹可被复制/诱骗（`spoof_flags`）。
- LPI 雷达（KD-R6）：截获距离 ×0.5、定位时长 ×2（docs/11 §6.1）；静默目标 `no_emission`。

### 7.2　输出与「不产生接触」

- 单站 ELINT 输出 `EmitterSignal`（§3.6），`produces_contact=false`；**不得**直接生成 `Track`/HUD 接触。
- 与已有航迹关联：按方位/时间/指纹相关（`correlate_signal`），只写该航迹的 `signal`/分类证据；仍不写位置。
- 多站交叉定位（2+ ELINT）：两方位线求交，输出 `TrackCandidate`（不是接触）：
  `pos, cov, confidence, baseline_km, gdop, source="elint_multistation"`；  
  仅当交叉误差 < `fix_gate_km`、两站时间差 < `max_time_skew_s`、指纹/频率相关时，才允许升 L2 候选；需由融合/确认（例如雷达/光学验证或指挥确认）才成为正式航迹。  
- 铁律：**ELINT 不产生身份 L4**；指纹匹配最高支撑 L3（舰级/雷达型号），confidence 标注；不明不自动判敌。
- 信号可用于「暴露测量」：我方的主动雷达/IFF/通信/干扰被敌 ELINT 截获 → 进 `exposure`/`elint_hits`，由同一总线发布。

### 7.3　COMINT（通信侦察）

- 与 ELINT 区分：ELINT 收发射源参数（雷达/IFF/干扰），COMINT 收通信内容（语音/数据/链路）。
- 输入：通信发射事件（`CommsObservation`：from/to/mode/text/encryption）；被动接收机在频段/链路内可截获。
- 输出：`comms_content{text, mode, encryption, from, to, confidence}`、链路关系/指挥链、延迟；**不是**传感器观测，不产生位置/等级（除非内容里明确坐标且经情报确认）。
- 加密：可拦截但不可直接解码（`encrypted=true`，只给元数据/流量分析）；关键内容由剧情/任务脚本显式给出，不能自动“解码”。
- 通信欺骗/注入：见 §8；COMINT 可发现“链路异常/呼号不符”，但不得自动判敌。

### 7.4　API 与 probe

```gdscript
sensor_authority.elint_state(observer_id) -> Dictionary
sensor_authority.signals(observer_id := "", since_t := -1.0) -> Array[EmitterSignal]
sensor_authority.correlate_signal(signal_id, track_id) -> Dictionary
sensor_authority.triangulate_signals(sig_a, sig_b) -> Dictionary   # 多站
sensor_authority.comint_events(since_t := -1.0) -> Array
```

probe：强源/弱源/超距/静默/LPI/指纹匹配/未知指纹/假信号；单站不产生接触；两站交叉误差/门限/时间同步/指纹相关；COMINT 加密不解码；ELINT 不写 hostile；同一 seed 确定性。

## 8　电子战与通信对抗（EW/信息作战）

> 目标：干扰/压制/诱饵/假目标/静默/通信欺骗全部成为**同一事件/状态总线**上的 `EWEffect`，由统一 authority 结算；禁止独立 EW 脚本维护第二套威胁/环境。

### 8.1　效果分类

| 类别 | 作用域 | 主要效果 | 反制 |
| --- | --- | --- | --- |
| 噪声干扰（E-01） | 雷达/通信接收 | 雷达 R_eff/Pd 下降（最低 30%）；通信误码/延迟 | 跳频、多基地、反辐射、关机 |
| 欺骗干扰（E-02） | 雷达 | 假回波/假批号；距离-功率不匹配、不机动 | 多传感器交叉、光学/IR、IFF |
| 诱饵/箔条/假目标 | 雷达/光学 | 额外假接触/回波；短寿命、漂移 | 轨迹/燃料/热特征验证 |
| 通信干扰（E-03） | 无线电链路 | 延迟 2→40 s、丢包、误执行 | 激光/中继/红外/可见光 |
| 通信欺骗/注入 | 指挥链 | 假命令/假呼号；延迟/来源可疑 | 加密、呼号/密钥、交叉确认 |
| 静默/EMCON | 自身/敌方 | 主动传感器/通信关闭；被动仍工作 | 被动探测、ELINT 侦听 |
| 激光告警/致盲 | 光学/激光 | LWR 告警；光学 dazzled/短时失明 | 滤光、机动、备份通道 |

### 8.2　统一公式/参数（沿用 docs/11 §6、docs/05 §5）

- 雷达噪声干扰因子：`jam_factor = 1 − jamming × (1 − 0.30) × (1 − jamming_resist)`；`jamming∈[0,1]`；R_eff = 基准 R_eff × jam_factor。
- 通信干扰延迟：`latency = lerp(2 s, 40 s, comms_jamming)`（无线电；激光不受影响但需 LOS）；丢包/误解概率随 `comms_jamming` 上升。
- 干扰机暴露：干扰机本身是最强发射源；敌 ELINT 可截获/测向/定位（含多站），并进入 `exposure`。
- 欺骗假目标：`phantom=true`，`range/power` 不自洽、无 `Δv`/热特征/历史机动；可被二次传感器交叉验证移除；假目标数量受干扰机能力限制。
- 静默/EMCON：主动挂载强制 `enabled=false`；切换有 `emcon_settle_s`（1–2 s）；被动传感器常开不增加暴露。
- 激光/光学对抗：`dazzle` 降低光学 Pd/致盲时长；LWR 只给告警方位（±10°），不产生接触。
- 效果叠加：同类取最大/并联（按模型定义）；不同传感器不同效果；效果必须带 `source_id`/`target_id`/`t_start/t_end`/`evidence`。

### 8.3　进入同一总线的方式（必须）

1. 干扰机/诱饵/通信欺骗不是独立“世界脚本”，而是**实体/挂载的发射行为**；
2. 发射行为产生 `EWEffect`（§3.7）→ `EventBus`；
3. `SensorAuthority` 在每个探测步骤读取当前生效的 effect → 形成 `EnvironmentFrame.jamming/comms_jamming` → 统一公式；
4. `core` 合并效果（航迹假标记/命令延迟/链路状态）→ 仍只有一个 `TrackTable`/命令状态机；
5. UI 只显示 `ew_effects` 摘要/独立窗；不直接改状态。

### 8.4　验收（probe 必测）

- E-01：jamming 0/0.7/1.0 时 R_eff 比例符合公式（0.7 → 0.608 @ resist 0.2；1.0 → 0.30）；干扰机被 ELINT 截获；
- E-02：假目标被标记 `phantom`，跨传感器验证可移除；假目标不产生真实航迹等级/身份；
- E-03：radio `comms_jamming` 0/0.5/1 → 延迟 2/21/40 s；激光链路不受 radio 干扰（LOS 条件下）；
- EMCON：主动挂载 off，被动探测/等级不因此消失；切换有延迟；
- 通信欺骗：产生可疑命令事件但不得自动改变裁决/证据；需玩家/审计确认；
- 同一 seed 下 effect 序列确定、可回放、可序列化。

### 11.3　数值验收（摘要）

- `Radar`: R_eff @ RCS10 = 30,000 km；RCS 变化按 ^0.25；jamming 0.7 → ×0.608（resist 0.2）；track ring 15,000 km。
- `TWS`: 6 通道；SEARCH→DETECT→ACQUIRE→TRACK→STARE→FIRE_CONTROL；失锁/重捕；FC quality≥0.85。
- `VIS`: 15,000 km 50 m 目标 N_px≈3.2 → 可分类；30,000 km→1.6→不可分类；锁定时间按 R²；阴影 lost；IR 4 s 锁定且 L1。
- `IFF`: 2,000 km；no_reply/faulty/wrong_code 不判敌；正确应答需注册库才 L4；缴获码 confidence≤0.5。
- `ELINT`: 60,000 km 强源可截获；bearing σ=1°；静默 no_emission；单站不产生接触；两站定位误差门限；指纹匹配 L3 置信度。
- `EW`: 噪声 jam factor 0.30 下限；通信延迟 2→40 s；假目标不产生真实等级；EMCON 关主动不开被动。

| R5.5 | EW/EMCON/通信效果进总线（shadow）：干扰/欺骗/诱饵/静默/通信干扰；环境帧统一 | UI 加告警摘要 | EW probe；无独立脚本 |
