## 1　通信格式

统一格式：

```
[发信者至收信者]-[通信方式缩写]-[通信内容]
```

- 例：`[哈马丹至远地点]-[LD]-[[9001] IFF 未应答，须进一步确认。完毕。]`
- 中文正文里保留全角括号；数据层可拆成 `from/to/mode/text` 四个字段，UI 再拼。
- 通信方式缩写：

| 缩写 | 方式 | 延迟 |
| --- | --- | --- |
| `LD` | 激光直连（Laser Direct） | 0.3–2 s |
| `LR` | 激光中继（Laser Relay） | 8 s |
| `RDO` | 无线电（Radio） | 2–8 s |
| `IR` | 红外（Infrared） | 2–8 s |
| `VIS` | 可见光（Visible） | 秒–分钟 |

- 不再用“公开频道”这种模糊写法；敌方通告用 `RDO`（法律广播），战术通信用 `LD/LR`。
- 教学提示、副官建议、手册**不进通信流**；通信流只放角色之间的真实通话。

## 2　四位数批号

参考 Nebulous/预警机的四位数 track 编码；本作约定：

| 段 | 用途 | 例 |
| --- | --- | --- |
| `1000–1999` | 友军/已知 | 1000 远地点，1001 哈马丹，1002 渡口，1003 望楼，1004 深井 |
| `2000–2999` | 敌军/清算署 | 2001 AV-4412 传唤者 |
| `9000–9999` | 不明/民用/虚警 | 9001 谷神-2，9002 CH-IR2 虚警 |

- 批号是**融合系统的编号**，不是舰名/舷号；无线电里报“目标编号”，图上显示小号。
- 失去跟踪后批号保留、等级降级；不重新编号。
- 真实 AWACS/EWR 的分类逻辑只借“按类别分段 + 4 位”这个习惯，不照搬具体条令。

## 2.5　敌我身份与政治分类

L1–L4 是**探测/识别等级**（看得多清）；身份是**政治上是谁**——两者分开显示。

| 身份 | English | 定义 | UI 色彩/符号（提案） |
| --- | --- | --- | --- |
| 待定 | Pending | 刚发现，还不知道是什么 | 灰；虚线方框/问号 |
| 未知 | Unknown | 雷达看见，但 IFF 无回应、ELINT 无特征码，无法判明 | 琥珀；菱形 |
| 假定友好 | Assumed Friend | 加密 IFF 应答、飞行计划比对或 PPLI 广播，但尚未完全确认 | 浅蓝；虚线圆 |
| 友方 | Friend | 己方/盟军资产，身份确认 | 薄荷绿；实心圆 |
| 中立 | Neutral | 民间船只或其他非参战国资产 | 灰绿；方形 |
| 可疑 | Suspect | 表现出不友好举动，高度怀疑是敌军，但未满足交战规则 | 橙；三角形 |
| 敌方 | Hostile | 确认敌对目标，满足交战规则 | 红；菱形/实心 |

- 身份变化：`Pending → Unknown → Suspect/Hostile` 或 `Pending → Unknown → Neutral`；友军可 `Assumed Friend → Friend`。
- 身份不自动判敌：IFF 无应答只能到 Unknown/Suspect，不能直接 Hostile；Hostile 需要证据 + ROE。
- 接触行显示：`[批号] 身份 · L级 · 方位/距离`。
- 图上符号按身份区分，不只靠颜色（色盲友好）：待定虚线框、未知菱形、假定友好虚线圆、友方实心圆、中立方形、可疑三角、敌方红色菱形。
- 第一关初值：
  - 1000 远地点 / 1001 哈马丹 / 1002 渡口 / 1003 望楼 / 1004 深井：Friend。
  - 2001 AV-4412 传唤者：先 Unknown，光学分类后 **Suspect**（它是清算署军舰，但尚未满足交战规则）。
  - 9001 谷神-2：先 Pending/Unknown，IFF/光学确认后 **Neutral**。
  - 9002 CH-IR2 虚警：Pending，交叉确认后移除/标虚警。

## 5　T1-11~14：裁决与对话选项

### T1-11　裁决提示（副官简报，不是通信）

- 拟改（`{mm:ss}` 用 `state.exec_left` 动态填）：
  `长官，执行窗口剩余 {mm:ss}。AV-4412 传唤者要求核验接管通知；斛港务请求阻止；渡口已请求武器释放授权。请裁决。`

### T1-12　三种结局的对话选项（玩家向署方的回复）

| 选项 | 发信者→收信者 | 通信方式 | 内容 |
| --- | --- | --- | --- |
| 认证交接 | 远地点→署方 | `LD` | 至署方，接管通知已核验，请开始交接程序。完毕。 |
| 援引第九条 | 远地点→署方 | `LD` | 至署方，依据《标高公约》第九条附则，现中止交接，请等待我方审裁。完毕。 |
| 拖程序 | 远地点→署方 | `LD` | 至署方，文书仍需复核，请提供附件三。完毕。 |

- 这些是**独立对话选项**，在裁决面板选完后进入通信流；不要塞进裁决提示或报告正文。
- 裁决面板本身是副官简报，不是通信。

### T1-13　结局 hint

- 认证：`签收接管通知，交接完成；斛港务声望下降。`
- 第九条：`中止交接；署方将发回执，进入审裁。`
- 拖程序：`要求复核；储罐可能断供。`
- 不再写“案卷 4471”。

### T1-14　报告正文：舰队内部事后报告

报告不走通信流，是舰队内部归档；格式：

```
舰队内部事后报告 / INTERNAL AFTER-ACTION
报告单位：AD 特遣群监督官
事件：斛 · 第七号裁定接管通知
裁决：认证交接 / 援引第九条 / 拖程序 / 开火
经过：……
证据：……
声望：……
建议：……
```

- 认证：`裁决：认证交接。接管通知已核验，交接程序完成。谷神-2 经核验为民用工作船，应答机故障，未实施敌对行为。未开火。斛港务提出异议。建议按程序归档，保留港务交涉记录。`
- 第九条：`裁决：援引第九条。依据《标高公约》第九条附则中止交接，已向署方发回执，等待审裁。未开火。建议准备听证材料。`
- 拖程序：`裁决：拖程序。要求文书复核，执行窗口结束，交接未完成。建议监控储罐供应。`
- 开火：`裁决：武器释放授权已执行。渡口号轨道炮两发命中谷神-2，民用船只损失，ROE 违规。建议封存日志，等待审裁。`

## 6　哨舰的传感器角色

- **现在代码里是错的**：`sensor_model.RACK_BLUEPRINTS` 把 `YW-R9` 雷达放在远地点，哈马丹只有 `CH-IR2 + CH-R0`。这是占位，不是设定。
- 正确角色：哨舰是舰队的 **AWACS/EWR 节点**。建议：
  - **哈马丹（哨舰）**：`YW-R9` 搜索雷达、`MS-OT2` 光学、`CH-IR2` 红外、`ELINT`、`CH-R0` 无线电。
  - **远地点（旗舰）**：`MS-IR9`、`ELINT`、通信/融合；不再装搜索雷达。
  - **渡口（炮舰）**：`LR-4`、`CH-IR2`、`CH-R0`；传感器差，依赖哨舰。
  - **望楼（中继）**：`MS-L2` 激光通信、`ELINT`、`CH-R0`；不是搜索节点。
- 第一关的“打开雷达”应该由玩家**命令哈马丹**执行，而不是远地点自动开；雷达一开就暴露，这也是教学点。

## 7　教学：副官建议 + 手册

- **副官建议**：单独 UI，一次性教学动画；只在第一次遇到某机制时出现；不是无线电，不是关卡提示。
- **教学手册**：完整可查，章节：指挥、变轨、目标识别、交战、ROE、损管。
- 通信流、裁决、报告里**不出现教学句**。
- 玩家设定：新官上任，接管 AD 特遣群；副官是熟悉舰队的人。具体名字/背景等 D2 世界格局再定。
