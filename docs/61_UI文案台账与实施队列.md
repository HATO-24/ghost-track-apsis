## 2. 设计口径与语义审校

保留深绿黑底、磷光绿重点、克制琥珀/红、细线框、矢量几何与大读数；关键文字清楚，主要动作位置固定。减少实现旁白，保留玩家必须知道的模式、数据有效性、阶段和阻断原因。诊断开关不授予新的情报权限，普通玩家/AI仍按授权视图读取。

已做代表性源码抽查，三项语义已修正：

- OrderService的QUEUED在DELIVERED后，表示已送达待执行/等待条件；与发送队列分开，不能译为未发送。
- 旧通信面板无匹配link也默认OPEN，候选必须显示未知/链路信息不可用，不能把代码默认当实况。
- `known=false`表示尚未形成识别评估；只有真实证据数为0时才称尚无证据。IFF证据/身份评估、ROE、TRACK/SOLUTION/FIRE授权分开。

台账原文里的ABORT/REVOKE还须按实际动作写：`_command_action`分别调用abort_order与reject_order，**不是撤销开火授权**；候选采用“中止命令/拒绝命令”，如设计要“撤回”则先明确阶段和API含义。不得以漂亮短词覆盖状态差异。

## 4. 现有实现证据与UI-02重点

正式基线的`PanelPainter`/`LayoutTokens`从`scripts/pal.gd`取V1色；`ui_tokens.json`另有palette。`fonts.gd`当前创建SystemFont（中文微软雅黑/黑体回退、等宽Consolas/Courier）；配置的字体文件路径不能证明已经加载。`TextMetrics.width`用真实Font量宽，但line_height/baseline仍落固定token/字号偏移；需测实际加载字体、ascent/descent/行高和缩放，不能仅改JSON后宣称界面生效。

1920×1080、100%下主操作/状态14–16px、次要12–14px是首轮有效可见尺寸建议；不是全token统一数值，也不是实机已通过。UI-02同时检查1600×900及约定缩放、长名、混排、命中区/焦点、字体回退与打包；截图与人工阅读必需。复古风格不豁免可读性。

## 5. 显示实现共同验收

- 业务状态→已授权只读视图→文案/格式→布局；动作→既有命令接口→真实反馈。文案层不改授权/ROE/资源/情报或世界观。
- 原始reason code与开发日志保留；正常显示做集中映射，未知错误如实标明并提供详情入口。无数据、过期、等待授权、失联、预览均不能变正常/0值。
- 不全局替换NOT READY，不删关键失败/演示/失效标识，不以内部ID补未知目标名；显示键尚未落代码时明确标候选。
- 变化影响到哪些控件就测哪些条件；不以字符串少了多少或headless通过替代实机操作/人工阅读。历史图、设计样页、真实运行截图分开归档。
- 设计/布局不抢选中或键盘焦点；未知/友/敌/选中兼用形状与文字，减少动态/辉光可关闭。正常更新不弹重复成功消息。
