## 7 ROE/授权

- 序章后解锁。

## 13　设施识别/港群实体迭代（第二阶段追加）

### 13.1 结论

L1–L5 港群、NESOSS、月同步轨道站走同一套：

```text
FacilityRegistry 数据
→ WorldState/PhysicsWorld 实体
→ 应答机/识别码
→ IFF/光学/ELINT 证据
→ PortService 港口绑定
→ UI 设施卡/港口页
```

不需要为每个港群单独写框架。

### 13.2 本阶段完成

- 设施注册表 `facilities_system.json`：L1–L5 全部已知站、NESOSS-01..06、月同步 3 站（命名 TBD）。
- 唯一 `facility_code` + `transponder_code`；按设施类型返回 station/port/fuel/tank/otc/relay。
- 每个设施带 parent_cluster / owner / services / ports / physical。
- GameSession 可选接入 FacilityRegistry。
- UI 设施页、港口页读取注册表。
- PortService 港口绑定设施 ID。
- 识别规则：应答机只提供 L4 证据，不自动判敌；无应答/错误码保持未知。

### 13.3 后续阶段

- 空间站内部结构、近景模型、内部舱段。
- 对接口/泊位碰撞体、详细进近走廊几何。
- 储罐热力学/流体/结构损伤传播。
- OTC 雷达真实波束覆盖、交通流调度仿真。
- 港群人口/经济/交通动态。
- 各港群全部设施的精确轨道/station-keeping 数据。
- 月同步站正式命名/归属/剧情。

### 13.4 识别边界

- 设施码/应答机码不是身份密码；可被缴获/伪造。
- 空间站应答机识别只到 L4 设施类型，不自动产生敌意。
- OTC 卫星/储罐/加注站可独立识别，不必先识别港群。
- 港口绑定是业务关系，不等于设施实体位置/对接口几何。

## 14　应答机行为层（第二阶段追加）

> 性质：对现实 SSR/IFF/ADS-B 的游戏化抽象，不是现实无线电协议仿真。

### 14.1 覆盖范围

- 舰只：`ship`，绑 world entity
- 空间站/港口/加注站/储罐/OTC/中继：`station/port/fuel/tank/otc/relay`，绑 FacilityRegistry
- 每实体有独立 profile：registration_code / transponder_code / facility_code

### 14.2 模式

- `mode_a` / `mode_c` / `mode_s`：代码/高度/选择式询问
- `mode_5`：需要 challenge/reply 与 crypto
- `station_beacon`：空间站/固定设施自动广播
- `adsb_like`：广播式位置/身份（游戏化）
- 舰只可 `silent`；空间站信标通常自动广播

### 14.3 状态

`normal / off / faulty / captured / spoofed / crypto_fail / expired / no_reply / wrong_code`

规则：

- `off/faulty/expired/no_reply/wrong_code/crypto_fail` → 无有效应答
- `captured/spoofed` → 可返回伪造应答，identity=unknown、置信度降级
- 无应答不代表敌意；不能自动判敌
- 重复码/未注册码进入异常事件

### 14.4 询问/广播

- 询问受 source/target/range/occlusion/jam/latency 影响
- 强干扰/超距/遮挡/超延迟 → 无应答
- 弱干扰 → 置信度降级
- 广播按 interval；空间站 beacon / adsb_like 可自动
- 输出 `track_evidence.v1`（L4 设施/身份证据）与 `transponder_event.v1`

### 14.5 序章触发

应答机事件不自带剧情文本，只输出 `trigger_id`：

- `ceres_no_reply`：谷神-2 无应答/故障
- `station_spoof`：空间站应答被俘获/伪造
- `unknown_code`：未知/错误注册码

StoryRuntime 可把 trigger 映射为 flag/evidence/对话/步骤推进。这样后续舰只/空间站都复用同一套触发，不写死在 UI。

### 14.6 与现实的差异

当前未实现：真实 1030/1090 MHz 询问应答、Mode A/C/S/5 时序、旁瓣/多站定位、真实加密算法、ADS-B 报文格式。只实现“身份/状态/置信度/触发”的可玩抽象。

高保真层后续可接：询问-应答时序、多站定位、抗欺骗、旁瓣、频率/功率、报文级 ADS-B。

## 15　IFF/EW 自动化深度（第二阶段追加）

### 15.1 目标保真度

不做波形级/密码学级仿真，做“决策可解释级”：

- 玩家看到的是身份估计、置信度、证据来源、矛盾、欺骗嫌疑、自动/人工状态；
- 后台有足够状态支撑干扰、欺骗、捕获、假目标、EMCON、自动化询问；
- 所有自动判定可追溯、可复盘、可配置。

### 15.2 当前已落地的行为层

- 应答机：模式/状态/加密/无应答/捕获/欺骗/触发（3P）。
- 识别自动化：多源证据融合、置信度、矛盾、欺骗嫌疑、自动询问、L3/L4 边界（3R）。
- EW 效果：noise_jam / deception / chaff / false_target / comms_jam / comms_spoof / emcon / lwr / laser_dazzle / decoy（3Q）。

### 15.3 自动化边界

- 自动询问只产生 query_request，不自动发射武器。
- IFF/应答单独不能把目标判为 hostile。
- 自动分类最高 suspect/L3；hostile 必须人工确认/授权。
- 两类独立证据 + confidence 阈值才可到 L4（friend/neutral/station）。
- 冲突/欺骗/捕获 → 降级、增加 spoof_suspicion，不静默覆盖。

### 15.4 后续阶段

- 自动交战/ROE 执行器（与 CombatService/授权链绑定）。
- 数据链融合的跨舰证据权重/延迟/带宽。
- 多站定位、旁瓣、真实欺骗回波（可选高保真）。
- 识别/EW 的 UI 可视化（置信度/来源/矛盾/自动询问状态）。
