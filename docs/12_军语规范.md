## 0　总则

1. **中文为主，英文为副。** 标签用 `中文 / ENGLISH`；英文只用于舰名、型号、标准缩写，不做装饰（❌ `TRACKS` 单独当标题）。
2. **一词一义。** 接触 ≠ 目标 ≠ 航迹；虚警 ≠ 假目标；战损 ≠ 损管；命令 ≠ 指令；识别 ≠ 分类（详见 §3）。
3. **第一次出现给全称 + 缩写**，之后可只用缩写；同一屏不重复解释。❌ 不同屏幕各写一半。
4. **数字具体、单位明确。** 不写「大量燃料」，写「四十一吨」；不写「很快」，写「45 秒」。方位三位数、距离、速度、时间都带单位。
5. **不确定就标「待核」。** 不引条令号；不用「按军规」当理由；不把英文当权威。

> 一句话：**这是给中国人读的军队终端，不是英文 HUD 的汉化补丁。**

## 1　术语分层

| 层 | 谁定 | 例子 | 规则 |
| --- | --- | --- | --- |
| **设定词**（专名） | 03–06 / 10 | 远地点级、传唤级、案卷 4471、回执、宽限期、监督官 | 以设定为准；本文不改设定名 |
| **军语** | 本文 | 接触、航迹、批号、不明目标、虚警率、武器释放 | 以本文为准；UI/无线电统一 |
| **工程词** | 05 / 11 / 工程习惯 | 状态向量、协方差椭圆、历元、LVLH、解算质量 | 技术语境用；不要硬翻成「军用」 |
| **UI 短码** | 09 / 本作 UI | L1–L4、EMIT、HOLD、PENDING、RX | 只作短码；中文标签另给，禁止裸用歧义短码 |

**三条纪律：**

- 不要把军语硬塞进设定名（如把「案卷 4471」改成「目标 4471」）。
- 不要把设定名当军语泛用（如把「回执」写成「ACK」、把「宽限期」写成「缓冲期」）。
- 不要在普通 UI 里裸用英文名词（`DAMAGE` / `TRACKS` / `HOLD`）；英文缩写表见 §4.2。

## 2　核心对照表

> 语域：**通用** = 空/海/天都可用；**空** = 空情/防空习惯；**海** = 海军习惯；**天** = 航天/轨道工程习惯。
> 「待核」= 公开译法不统一或本作未定，先按推荐写法用，定稿前拍板。

| 中文（推荐） | English | 语域 | 用法 / 边界（本作） | 禁用 / 易错写法 |

| 稳定跟踪 | stable track | 空·海 | 雷达在稳定跟踪距离内连续跟踪 | ❌ 稳定锁定 |
| 失跟 | track loss（待核） | 空·海 | 丢失跟踪；05：失去跟踪不删除，逐级降级 | ❌ 丢失目标 |
| 重捕 | reacquisition（待核） | 空·海 | 失跟后重新捕获 | — |
| 搜索 | search | 空·海 | 主动雷达/光学搜索模式 | ❌ 扫描（扫描是显示动作） |
| 威胁等级 | threat level | 通用 | 威胁分级；本作不显示数字条，只在内部/简报使用 | ❌ 威胁值（不是分数） |

### 2.2　传感器与对抗

| 中文（推荐） | English | 语域 | 用法 / 边界（本作） | 禁用 / 易错写法 |
| --- | --- | --- | --- | --- |
| 虚警 | false alarm | 通用 | 系统误报的告警/回波；无真实目标 | ❌ 假目标（假目标是敌情）；❌ 误报率（口语可，正式不用） |

| 诱饵 | decoy | 通用 | 实体/信号诱饵装置：热源气球、信号模拟器 | ❌ 把诱饵直接叫假目标（手段 vs 结果） |

| 辐射控制 | emission control（EMCON 命令） | 通用 | 13 §2 命令：雷达/通信/干扰开机或静默；状态叫「电磁管制/静默」 | ❌ 把 EMCON 当命令中文名；❌ 与「静默」混 |

### 2.5　指挥、流程与审裁

## 3　三个专项

### 3.1　虚警 / 虚警率 / 漏警 / 假目标 / 诱饵

| 词 | English | 定义 | 本作用法 | 禁用 |
| --- | --- | --- | --- | --- |
| 虚警 | false alarm | 系统把噪声/杂波/残骸误判为目标的告警 | 「CH-IR2 虚警」「虚警候选」；事件计数 `false_alarm_count` | 假目标 |
| 虚警率 | FAR（false alarm rate） | 单位时间或单位扫描的虚警统计 | 写清单位：次/小时 或 次/扫描；数据字段 `false_alarm_rate` | 把 Pfa 叫 FAR |
| 虚警概率 | Pfa（待核） | 单次探测/单次扫描出现虚警的概率（0–1） | 11 的 `false_alarm` 0.02–0.22 实际是 Pfa；建议字段改 `false_alarm_prob` 或注明 | 把 0.22 写成「虚警率 22%」而不说单位 |
| 漏警 | missed alarm | 真实目标存在而系统没告警/没检测到 | 与虚警成对统计 | 漏检（系统层） |
| 漏警率 | MAR（待核） | 漏警统计；单位同虚警率 | 报告「漏警率」时必须给样本量/单位 | 与 Pfa 混 |
| 假目标 | false target | 敌方制造/模拟出来的目标（含诱饵、欺骗信号产生的假航迹） | 电子战/诱饵语境 | 虚警 |
| 诱饵 | decoy | 具体的诱饵装置/信号 | 05 W-05 / E-02 | 假目标（手段≠结果） |

**三条硬规则：**

1. **虚警不是假目标。** 虚警 = 我们自己的系统犯错；假目标 = 敌人让我们犯错。
2. **虚警率必须有单位。** FAR 是 rate；单次扫描概率是 Pfa。11 的 `false_alarm` 是 Pfa，不是 FAR（见 §8 C-6）。
3. **漏警与虚警成对报告。** 只报虚警不报漏警，等于只说一半；UI 若显示统计，两个一起给（可只在简报/审裁里出现）。

### 3.2　不明目标 / 不明接触 / 不明信号 / 未识别目标

**判定顺序：**

```
有没有回波/航迹？
├─ 没有，只有辐射/信号 ─────────────→ 不明信号（ELINT/ESM；不出接触）
└─ 有
   ├─ 未确认是实体（残骸/反射/虚警候选） ─→ 不明接触 / 虚警候选
   └─ 已确认是实体目标
      ├─ 身份/敌我未知 ────────────────→ 不明目标
      └─ 识别流程未完成 ───────────────→ 未识别目标（状态）；判明后 → 分类 / 确认
```

| 场景 | 推荐写法 | 不要写 | 理由 |
| --- | --- | --- | --- |
| 接触列表里的未知航迹 | **不明接触**（未确认实体）/ **不明目标**（确认实体） | 未识别、未知、Unknown | 实体名不能是识别状态词 |
| ELINT 收到信号但没有航迹 | **不明信号** | 不明目标 | 没有位置，不能叫目标 |
| 07 第一关「不明 ≠ 敌意」 | **不明**（口语标记）/ **不明目标**（正式） | 未知、未识别 | 07 的教学词是「不明」 |
| 光学/雷达识别没完成 | **未识别**（作为状态）/ **未识别目标**（正式） | 把「未识别」当实体名 | 状态词 vs 实体名 |
| 谷神-2（应答机故障） | **不明目标**（07：坏掉的友舰） | 敌舰、未识别 | 05/07：不应答 ≠ 敌意 |
| 虚警候选航迹（P1c） | **虚警候选**（未确认）/ **虚警**（确认后） | 不明目标 | 它可能没有实体；确认后是虚警不是目标 |

> **对 P1c 的特别提示**：`state.gd` 当前把 CH-IR2 的那条航迹叫「未识别」，并在交叉确认后把 `cls` 改成「虚警 / FALSE ALARM」。这符合 P1c 的阶段性做法，但**术语上应分两段**：确认前 = `不明接触` / `虚警候选`；确认后 = `虚警`（不再当目标）。不要让它一直以「未识别」这个名字留在接触列表里。

### 3.3　接触 / 航迹 / 目标 / 批号 / 威胁

| 词 | 是什么 | 不是什么 | UI 用法 |
| --- | --- | --- | --- |

**英文对应：**

## 6　无线电通话模板

### 6.1　标准格式（03 §10.2；07 开场通话）

```
「收方，发方。报文。完毕。」
「发方，收方。请发。完毕。」
「接触。红外。方位零四七。距离八千。无识别。完毕。」
「收到。保持静默。完毕。」
```

规则：

- 先报单位、再报内容；方位三位数；距离带单位；不解释、不抒情。
- 「无识别」= 未识别（状态），不是「未识别目标」；正式报告可按 §3.2 改成「不明」。
- 敌人说话比我们礼貌：完整句、条款号、被动语态、不用缩写（03 §9、§10.2）。

### 6.2　接触报告模板

```
接触。被动红外。方位 047°。距离不明。等级 L1。完毕。
接触。主动雷达。方位 312°。距离 8,000 km。等级 L2。完毕。
不明接触。方位 302°。距离不明。可能为残骸/虚警。完毕。
不明信号。方位 118°。特征码 CH-IR2。未形成航迹。完毕。
```

### 6.3　武器释放 / ROE 模板

```
请求武器释放授权。目标：案卷 4471。完毕。
武器释放授权已批准。重复，已批准。完毕。
武器释放授权拒绝。重复，拒绝。保持仅自卫。完毕。
不得首先开火。重复，不得首先开火。完毕。
```

- 正式文本：**武器释放授权**；口语/无线电：**自由开火**。
- 不要写 `weapons free` 进中文 UI；不要在 ROE 卡上裸写 `HOLD`。
- 拒绝开火 = 「武器释放授权拒绝」；不是「不开火」（太口语）。

### 6.4　回执 / 报告模板

```
接管通知已收讫。回执已发。完毕。
执行窗口剩余 00:06:00。时标锁 1×。完毕。
报告：认证交接。无未经授权开火。完毕。
```

- 回执 = receipt（书面确认）；不要用 `ACK` 代替。
- 「已接收」是收到；「已收讫」是完成登记；UI 按语境选。

### 6.5　不该出现的说法

| 不写 | 原因 | 改 |
| --- | --- | --- |
| 「看起来像敌舰」 | 口语/不确定 | 「不明目标，等级 L1」 |
| 「好像有信号」 | 不专业 | 「不明信号，方位 ...」 |
| 「打不打？」 | 口语 | 「请求武器释放授权」 |
| 「收到了」 | 太口语 | 「收讫」/「已接收」 |
| 「自由开火」进正式文书 | 口语/ROE 状态 | 「武器释放授权」 |
| 「目标被摧毁」无评估 | 未经评估 | 「毁伤评估：命中/未命中」 |

## 7　写作检查表

写 UI / 无线电 / 简报前逐条过：

1. **中文主、英文副**：英文是不是只作舰名/型号/缩写？有没有装饰性英文？
2. **一词一义**：接触/目标/航迹/批号用对了吗？不明/未识别/未知统一了吗？
3. **虚警 vs 假目标**：有没有把系统误报叫假目标？虚警率给单位了吗？
4. **战损 / 损管 / 状态**：三者有没有混？
5. **ROE**：`HOLD` 是否有歧义？「武器释放授权」是否用了正式词？
6. **命令 ≠ 指令**：作战命令没写成指令吧？
7. **轨道词**：变轨/轨道机动/点火/持续推力没混吧？「节点」是否指停泊点？
8. **本舰/旗舰/选中舰**：有没有把选中舰叫本舰？
9. **舰名**：远地点号有没有写成「远地点」？「号」字同屏统一吗？
10. **缩写**：第一次出现给全称了吗？ELINT/RCS/CCS 这些有歧义的注了吗？
11. **数字**：方位三位、单位齐全、具体数值（不写「大量」）。
12. **敌人礼貌**：敌方无线电是否完整句、条款号、被动语态、不用缩写？
