## 1　栅格

### 1.1　规则

| 编号 | 规则 | 说明 |
| --- | --- | --- |
| R1 | **4px 基础格** | 所有**布局框**（面板、控件、行、命中区）的 position / size 必须是 4 的倍数 |
| R2 | **8px 节奏格** | 间距、行高、控件高度**优先**取 8 的倍数；做不到时才允许 4 的倍数 |
| R3 | 既有锚点例外 | `124`（内容上沿）、`876`（内容下沿）、`884`（下区上沿）只落在 4 格 —— 由 V1 版式与 `main.gd` 的 plot 决定，**本轮不改** |
| R4 | 文本不受 R1 约束 | 文字是基线排版，允许落在非 4 格位置；行内元素（徽标、刻度、≤8px 标记）跟随文字，不强行对齐 |
| R5 | 1px 分隔线 | 允许贴在面板 / 行内侧 1px（这是描边，不是布局） |
| R6 | 网格自检 | 新增矩形先问：`x % 4 == 0`、`size % 4 == 0`；间距先取 8/16/24 |

字号不在这版重切：V1.5 沿用 V1 的 7/8/9/10/11/12/13/18/24/26/30 连续档（改字号会改断行与信息密度）。换字体时再统一到 8/12/16/24/32 四档，见 §8。

### 1.3　布局推导

**水平**（1920）：

```

                     ↑ 面板内边距 16：内容 76 … 364                        内容 1556 … 1844
```

校验：`40+20+320+16+1128+16+320+20+40 = 1920` ✓

**垂直**（1080）：

```
40 bezel │ 72 顶栏 ─ 112 │ 12 │ 124 ─ 内容区 752 ─ 876 │ 8 │ 884 ─ 下区 156 ─ 1040 │ 40
```

校验：`40+72+12+752+8+156+40 = 1080` ✓

**顶栏列**（140 等距，右端落在面板右沿 1860）：

```
60 时钟 │ 520 分隔 │ 548 ─ 通告 420 ─ 968 │ 1288 分隔 │ 1300 LINK │ 1440 时标 │ 1580 Δv │ 1720 ROE │ 1860
                                                        └──────── 140 ────┴── 140 ──┴─ 140 ─┘
```

本轮把 ROE 列从 1730 **收到 1720**，让四列成为 140 等距、右端正好收在 1860（面板右沿）。

### 1.4　自检方法

- 改完 `hud.gd` 后跑 headless（§7），再截 1920×1080 图；
- 用像素探测复核关键边：`1px` 线在 1920 下通常占 1 个物理像素（本机截图实测：条左边 779、右边 1139）；
- 对齐不是“看起来差不多”：**每个控件都要说得出它对的是哪根线**（中轴 / 区界 / 面板内沿）。

## 3　传感器条 / 下拉的最终位置（本轮核心裁决）

### 3.1　两个候选（交接包里留的问题）

| 候选 | 位置 | 字面优点 | 实测问题 |
| --- | --- | --- | --- |
| **A 720 居中**（现状） | `(720, 136, 360, 26)` | 放在地图上部，避开标题与罗盘 | **不是真居中**：中心 900，地图中轴 960，差 **60px**；既不贴边也不对轴 |
| **B 420 贴地图左缘** | `(420, 136, 360, 26)` | 与地图内容左列对齐（420 = 396+24） | 会压住 plot 标题块；下移又压住图层注记（见 §3.4） |

### 3.2　决定

> **选 A（居中），但 720 要修正为 780。**
> 传感器条是“改变中区图层”的模式开关，它属于中区的**中轴**，不属于中区的边缘。

最终坐标（已落地）：

```gdscript
const MAP_CX := 960.0                       # 396 + 1128 / 2
const BAR_W := 360.0
const BAR_H := 28.0
const BAR_X := MAP_CX - BAR_W * 0.5          # 780
const SENSOR_RECT := Rect2(BAR_X, 136, BAR_W, BAR_H)               # (780, 136, 360, 28)
const MENU_HEAD := 28.0
const MENU_ROW := 44.0
const MENU_ROWS := 6.0
const MENU_RECT := Rect2(BAR_X, 168, BAR_W, MENU_HEAD + MENU_ROW * MENU_ROWS)  # (780, 168, 360, 292)
```

- 条：`780…1140 × 136…164`，中心 **960** = 地图中轴 = 本舰 000 轴 = 顶栏中心。
- 下拉：与条同宽同轴；`168` = 条底 164 + **4**；高 `292` = header 28 + 6 行 × 44；底边 460。
- 对齐规则写成公式：`bar_center = map.x + map.w / 2`。地图矩形以后变（压平 / 旋转 / 新布局），照这个公式重算即可，**不再出现 720 这种手填值**。

### 3.3　理由

1. **语义**：条是“看哪里”的开关，属于中区；中区的身份边界是它的中轴，不是左缘。左缘归地图标题（“战术态势”），右缘归罗盘 / 光学通道。
2. **可证明的对准**：`960` 是地图视口中轴、也是顶栏中心。截图实测：条左边 779、右边 1139 → 中心 959.5≈960。注意：ENG-01 的自由旋转会让**本舰**离开 960（相机可动），但**视口中轴不动** —— 所以对齐规则只依赖视口中轴，不依赖本舰位置；这也正是“对轴”比“对本舰”稳的原因。
3. **不改别人文件**：420 方案想成立，必须动 `plot.gd` 的标题块位置（本任务禁止），或者接受压住标题 / 压住注记（见下）。
4. **遮挡代价最小**（下拉必然压地图，比较压什么）：
   - 居中下拉压住：顶部 `000` 刻度、**点火幽灵注记**（Phase 2“命令”才用到）、顶部环线；
   - 贴左下拉压住：**“方位 302° · 距离未知 · 陈旧 41s”** —— 这是Phase 1“读”的教学道具（不明≠敌意、仅方位接触）；
   - 下拉是“选图层”的瞬时操作，选完即关；牺牲Phase 2的道具、保住Phase 1的道具，更合理。
5. **规则数量**：贴左会引入第三条左内距规则（标题 16 / 注记 24 / 条 24），居中只引入“中轴”一条。仪表化的界面，对齐规则越少越稳。

### 3.4　为什么不是 420（实测证据）

- `plot.gd` 标题块实测占屏 **x 402…约 560、y 137…197**（在新版 plot 里是 5 行：战术态势 / TACTICAL PLOT / STATION FRAME / DATUM / EXEC WINDOW，另有一个闪烁点）。
- 条若放 `420…780 × 136…164`，会盖住标题块 **98px**（420…约 520 是文字列）——标题被切掉一半，比“没对准”更糟。
- 想把条下移避开标题，至少要让到 `y ≥ 200`；但 plot 的图层注记现在从 `y = 220 / 232` 开始（“IRST 明视 IR-9 / 被动红外”“NO RANGING · BEARING ONLY”）—— 条会盖住它自己要解释的图层注记。
- 结论：**420 方案在本轮不成立**。若未来重排 plot 左上角（标题移到别处），可以重议；届时本条规则仍需满足「对中轴或对区界」之一。

### 3.5　下拉打开时的遮挡（明确记录，不假装没有）

居中下拉覆盖地图顶部中间（plot 局部约 `384…744 × 44…336`）：
- 覆盖：顶部 `000` 刻度带、命令 / 变轨幽灵注记一带（Phase 2“命令”才用到）、顶部环线；
- 不覆盖：302° 陈旧方位接触注记（Phase 1“读”的教学道具，在左半区）、罗盘、光学窗、图例、基准注记、左右纵栏。

注意：ENG-01 把地图改成可旋转 / 可压平之后，具体被覆盖的接触会变；判定标准不变：**先压Phase 2的道具，不压Phase 1的道具**。

这是**有意的取舍**。彻底的解法不是挪下拉，而是 §5：传感器架最终进右区，地图上不再开下拉。

## 4　V2 一次性动效在 V1.5 的规则

### 4.1　先分清两种动效

| 类型 | 定义 | 例子 | 规则 |
| --- | --- | --- | --- |
| **一次性动效** | 由一次状态切换触发，播完停住，不循环 | 冷启动、菜单揭示、传感器硬切 | 必须登记；有限时长；可复现 |
| **持续动效** | 表示“某系统正在工作”，随状态持续 | 雷达扫描线、IR 脉冲、扫描线、光标闪烁 | 允许持续，但只做状态指示，不做装饰 |

**一条总则：一次性动效只在“状态真的变了”时播；连续数据不配动画。**

### 4.2　V1.5 现有一次性动效清单

| # | 名称 | 触发 | 状态变量 | 时长 / 节奏 | 实现位置 | 可跳过 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 冷启动 | 进入场景 | `state.boot_t` | 1.7s；自检逐行 `t*8`；扫描线 1.55s | `hud._draw_boot` | **否（待补）** |

| 5 | 时标 / 暂停 | 输入 | — | **0（瞬时）** | `main` / `hud` | — |

### 4.3　规则

| 编号 | 规则 |
| --- | --- |
| A1 | **一个变量只驱动一个动效**；一次性动效用独立计时器（`boot_t` / `menu_t` / `sensor_fx_t`），不许拿全局 `_t` 当计时器 |
| A2 | **交互反馈 ≤ 0.4s**。`boot` 是唯一超过 1s 的一次性动效 |
| A3 | **一次性动效不阻塞输入**（`boot` 除外），也不改变命中区；动效期间点击必须按最终布局判定。地图拖动 / 缩放必须跳过 `hud.consumes(p)`（`main.gd` 已按此接入：先问 HUD，再转地图） |
| A4 | **映射表驱动**：`boot_t<1.7` → 只画 boot；`menu_open` → 揭示；`sensor` 变化 → 硬切；其他状态变化 → 无动效 |
| A5 | **V1 视觉语言**：选中 = PANEL2 + 2px PH 左条；硬切块 = `BG`、80px；不使用 V2 的整行酸绿实心 |
| A6 | **可复现**：随机只允许在初始化时用固定 seed（象限顺序固定 1-2-4-3；硬切 seed 4471）；截图 / GIF 必须能重跑出同一帧 |
| A7 | **安全**：单次亮闪 ≤0.14s；大面积亮色一次 ≤0.38s；不允许 >3Hz 闪烁；黑块硬切不得叠加超过 2 层 |
| A8 | **登记制**：新增一次性动效必须在 §4.2 表登记触发 / 变量 / 时长 / 可跳过性，否则不合并 |

## 5　per-ship 传感器架 · 布局提案

### 5.1　问题

V1.5 现在用的是 V2 遗留的**全局传感器下拉**（6 项：S-07 / 听-3 / R-9 / 光学 / MK-12 / ELINT）。这和 [`07`](07_第一关_监督交接.md) §4 冲突：

> **传感器架按舰载**：选中舰 → 打开它的传感器列表；列出厂商、型号、距离、延迟、虚警率，可开机 / 关机。

第一关的教学动作就是“选中哈马丹 → 打开它的架（CH-IR2 / CH-R0）→ 再用远地点号的 MS-IR9 交叉确认”。全局菜单把这个动作抹平了。

### 5.2　原则

1. **传感器属于舰**：列表 = 选中舰的；切舰 = 换架。
2. **架在右区**：右区本来就是“算”（选中单位详情），架是单位配置，属于右区；**地图上不再开第二个下拉**。
3. **开 / 关是动作**，不是图层开关：ON/OFF 走 sim 规则（开机即暴露），UI 只负责显示与点击。
4. **不弹窗**：V1 没有弹窗；用面板页切换。

### 5.3　布局：右区 UNIT 面板「整页切换」

### 5.5　交互与规则（UI 侧只负责表现）

1. 点地图传感器条 → 右区切到“传感器架”页（**不盖地图**）；再点条 / 点页头“返回舰况 ✕” → 切回。
2. 点行 → 该模块成为当前地图图层源；若模块关机，点击先提示“需开机”（或按 sim 规则拒绝）。
3. 点 ON/OFF → 开关机（sim 规则：R-9 开机 → 立刻暴露；听-3 只给方位；光学凝视计时推 L3；MK-12 2,000 km 内推 L4；ELINT 出“信号”不出“接触”）。
4. 换选中舰（左区）→ 架页跟着换；页保持打开状态。
5. 地图左上图层注记（plot `y=180/192`）改为**多来源注记**，最多 3 行；行的“来源”= 舰名 · 型号。
6. 条退化：`[SENSOR] [glyph] 哈马丹 · CH-IR2 [被动红外] ▾`；点它只做“打开架页”，不再弹下拉。

### 5.7　迁移四步（V1.5 → 按舰）
