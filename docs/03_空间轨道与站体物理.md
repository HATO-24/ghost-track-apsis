# 03 空间、轨道与站体物理

> 状态：权威。依赖：`02`。实现层：`game_v17/framework/sim`。

## 1 精度目标

游戏需要的是**可玩、可复现、教学上正确**的地月系轨道，而不是航天任务级星历。分层：

| 层 | 内容 | 精度目标 |
| --- | --- | --- |
| 全局星历 | 太阳/行星/月球的低阶位置 | 游戏内 km–百 km 级，按距离缩放 |
| 地月局部 | 地球/月球/太阳引力 + 实体积分 | 近地/地月转移 km 级，6 天内可接受 |
| 近距操作 | 相对运动/接近/对接 | m–km 级（本地 LVLH） |
| UI | 显示舍入/缩放 | 不参与物理 |

物理层用 double canonical state；Godot `Vector3` 只用于视图。

## 2 全太阳系 JPL 可行性

**技术上可行，但不建议作为运行时主方案。**

可行方式：

- 使用 JPL DE440/DE441 的 Chebyshev 系数，或 SPICE 内核；
- 预计算太阳/行星/月球在任务时间窗内的位置/速度表；
- 运行时插值 + 局部 N 体积分。

工程代价：

- 数据体积（完整 DE441 数十 GB；裁剪到 2193 年窗口 + 少量天体可到 MB 级）；
- 许可/署名/再分发条款；
- 加载/内存/线程；
- 时间系统（TDB/UTC/闰秒）与坐标系；
- Godot 纯 GDScript 读取 SPICE 需要原生扩展或预转换。

结论：

- **默认方案：JPL 派生紧凑星历**——从 DE440 提取任务窗口内太阳/月球/行星的低阶 Chebyshev/Kepler 拟合，保留太阳/月球/地球/主要行星；数据规模可控，误差对游戏足够。
- **允许方案：完整 SPICE**——作为“高保真模式”可选，不进入默认发行包。
- **禁止方案**：用网上抄来的平均根数冒充 JPL；所有星历必须标注来源、时间窗、误差。

## 3 坐标与时间契约

- 时间：仿真 T+（秒）+ epoch UTC；所有事件带 `t`。
- 惯性系：地心/日心 ECI。
- 旋转系：地月旋转系（CR3BP）用于轨迹/显示。
- 局部系：LVLH/舰体/港口系。
- 单位：km、km/s、s、rad；UI 可换算。
- 每个 view model 带 `source_t`、`age`、`frame`、`quality`。

### 为什么当前 float32 不够

38 万 km 处 float32 分辨率约 0.03 km；光学 IFOV、对接、站体尺寸会失真。解决：

- 物理/状态用 double（Array/PackedFloat64Array 或自定义 Vector3d）；
- 近距离用相对坐标/LVLH，不用绝对大数；
- 视图再转 float32。

## 4 动力学模型

### 4.1 局部高精度

- 地球 + 月球 + 太阳第三体；
- 可选 J2、月球非球形、太阳光压；
- RK4 固定步长（≤60 s）；后续可换辛积分/自适应；
- 变轨用脉冲/有限推力；质量/燃料随 Δv 变化；
- 姿态/角动量独立；传感器安装矩阵随机体。

### 4.2 全局

- 太阳/行星用紧凑星历；
- 地月局部用高精度积分；
- 跨区域用分层坐标，不做“一张全太阳系绝对坐标”。

## 5 实体状态

每个实体至少：

```text
id, kind, side, name, class, faction
state: r, v, mass, fuel, attitude, angular_velocity
orbit: frame, epoch, root/state
ports[], sensors[], weapons[], damage_sections[]
comms_nodes[]
```

舰船/站体/储罐/穿梭机/拖船都遵循同一 schema；站体可有固定轨道/站保持推进。

## 6 站体与港口

- 站位按真实轨道/站保持计算，不以固定屏幕坐标存在。
- 站体数据保留：质量、半径、自转、端口、船坞、储罐、加注能力、交通管制节点。
- UI 只显示符号/标签；近景模型不属于物理层。
- 空间站构造按 `02`：O’Neill 圆柱 / Stanford 环面；物理层用等效半径/质量/转动惯量，不做全结构仿真。

### 港口操作

- 入港/并轨/对接/加注/船坞维修/拖曳/派遣穿梭机；
- 交通管制：进近走廊、等待区、时间窗、许可、优先级；
- 命令必须经过命令/通信服务，不直接改世界。

## 7 交会/对接/拖曳

- 相对运动：LVLH/Hill/CW + 数值积分；
- 接近走廊：轴向/横向/半角/接近速度；
- 对接端口：位置/朝向/半径/类型/兼容；
- 判定：距离/横向/对齐角/接触速度；
- 拖曳：拖船-目标约束/相对速度/张力上限/失败；
- 失败原因可显示、可回放。

## 8 轨道规划

- 自动：目标/时间窗/Δv/暴露约束 → 候选转移（Lambert/CR3BP 打靶/优化）；
- 手动：玩家设脉冲/时间/目标，系统校验可达性；
- 半自动：玩家选约束，系统给方案，玩家确认；
- 全自动：授权后执行，可中断；
- 战斗机动：保持/接近/脱离/规避/指向/点火，带 Δv/暴露/风险；
- 规划结果进入命令队列，不直接改轨道。

## 9 当前技术验证资产

- `transfer_planner.gd`：Lambert + CR3BP/RK4 打靶，L4→L1；
- `fleet_transfer.gd`：5 舰独立传播；
- `cislunar_physics.gd`：CR3BP/RK4、L 点、相对运动、接近走廊、对接几何；
- `navigation_model.gd`：节点/路线/许可/机动状态机；
- 这些是验证资产，不直接等于最终权威层；最终需按 `09` 接入单一世界。

## 10 验收

- 6 天转移到达误差 ≤ 10 km（教学关可放宽到 1000 km，但必须标注）；
- 5 舰独立状态可区分；
- 对接判定可复现；
- 物理层无 float32 大数漂移；
- 存档恢复后轨迹连续；
- 星历来源/时间窗/误差写入文档与 UI 页脚。
