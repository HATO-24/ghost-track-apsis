# 09 系统架构与数据契约

> 状态：权威。所有实现必须遵守；旧框架的临时 bridge/state 仅作参考。

## 1 分层

```text
Content (JSON/CSV/本地化)
  ↓
Core Services
  - Physics World (authoritative, fixed tick)
  - Time Service
  - Entity/Attitude/Mount
  - TrackTable (single writer)
  - Comms/Orders
  - Sensors/EW
  - Story/Trust/Morality/Evidence
  - Save
  ↓
View Models (read-only, timestamped)
  ↓
UI (Control+Theme; 地图自绘)
```

UI 禁止写世界；所有玩家操作生成 Command/Intent，经服务处理后再产生事件。

## 2 单一权威

- 一个物理世界；一个时钟；一个 TrackTable 写者。
- 传感器/信息作战不写等级/身份/威胁；只提交 Observation/Evidence。
- 剧情状态单写者：Story Service。
- 命令/通信状态单写者：Orders/Comms。
- 存档单写者：Save Service。

## 3 时间与 tick

- 仿真 tick 固定（物理 ≤60s；传感器按刷新率；UI 60fps）。
- 渲染插值不反向写物理。
- 时标只改变 tick 的推进，不改变事件语义。
- 所有事件带 `t`；回放按事件重建。

## 4 事件总线

事件类型：

```text
Observation, Evidence, TrackUpdate,
OrderIssued, OrderDelivered, OrderExecuted, OrderFailed,
CommsSent, CommsDelivered, CommsFailed,
EWEffect, DamageEvent, DockEvent,
StoryEvent, TrustChanged, MoralityChanged,
Save/Load
```

事件 schema：`id, type, t, source, target, payload, confidence, text_key`。

## 5 DbC（Design by Contract）

每个系统入口必须有：

- Preconditions：单位/坐标/时间/ID 合法；
- Postconditions：状态/事件/view model 更新；
- Invariants：UI 只读、单写者、时间单调、存档一致。

示例：

```text
TrackTable.apply_evidence(evidence):
  pre: evidence.t <= now, target exists, source valid
  post: track.level >= old, evidence appended, no duplicate
  invariant: only TrackTable writes level/identity/threat
```

违反契约必须报错/回退，不静默吞。

## 6 View Model

每个 UI 数据带：

```text
schema, t, source_t, age_s, frame, units,
quality, stale, warnings
```

UI 显示“过期/延迟/不确定”，不能把旧数据当实时。

## 7 存档（任意时刻）

必须保存：

- 世界实体状态/轨道/姿态/损伤；
- 在途命令/通信/计时器；
- 传感器观测/TrackTable/证据；
- 剧情 flag/信任/道德/声望；
- RNG seed/时钟/存档版本；
- UI 布局/选中/过滤器（可选）。

策略：

- 原子写入 + 备份；
- schema 版本迁移；
- 读档后事件队列重建；
- 三色圆点：存档/存档回主菜单/存档退出。

## 8 内容与本地化

- 所有舰名/站名/文本/数值来自内容文件；
- 文本 key + 多语言表；
- 传感器/舰船型号不得写死在代码；
- 内容校验工具（缺失 key/重复 ID/非法单位）。

## 9 测试

- 单元：数学/物理/传感器/命令状态机；
- 集成：单一世界 + 事件总线；
- 回放：确定性；
- 存档：随机时刻往返；
- UI：分辨率/字体/长文本；
- 性能：tick/加载/内存。

## 10 迁移策略

- 现有 `transit.tscn`/`transit_hud.gd` 作为技术验证，不进入最终架构。
- 现有 `framework/sim` 模型作为算法来源，逐步迁入服务。
- shadow → authoritative：每系统 feature flag + 对比 + 回退。
